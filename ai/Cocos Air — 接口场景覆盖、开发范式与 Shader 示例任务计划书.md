# Cocos Air — 接口场景覆盖、开发范式与 Shader 示例任务计划书

> 评估日期：2026-09-25。本文是实施计划，不宣称下列缺口已修复。范围为 Web Code First SDK、示例及开发文档；沿用现有 Cocos 原生 `Scene` / `Node` / `Component` / `Material` 体系。

## 1. 现状与结论

| 主题 | 仓库证据 | 判断 |
| --- | --- | --- |
| 单点示例 | `examples/files.json` 当前登记 58 例，含 2D/3D 物理、UI、动画、glTF、音视频等；`docs/manual/examples/manual-mini-game/` 另有吃金币小游戏 | 有基础，但不能把单接口演示等同于复杂组合或完整产品场景 |
| API 覆盖 | `docs/api-coverage-report.json` 的 2026-09-24 快照：8,060 单元，2,589 个 `coverageRequired`；Core verified 56/816，Important verified 20/1,773；Advanced required 为 0，门禁不适用。报告另有 5 个 stale evidence examples、1 个 schema gap | 既有覆盖体系可复用，先校验证据时效和分母，再补高价值缺口；不得用 claimed/attested 冒充 verified |
| 开发范式 | `docs/guides/06-code-first-getting-started.md`、`examples/hello-cube/main.js` 已说明启动与 `Component.update`；现有例子同时使用根目录 `main.js`、`main.ts` 和 `src/main.ts`，`material-basic/src/main.ts` 仍有一行多语句与 `var` | 需要统一用户工程的脚本组件结构、构建运行流程和示例样式；不要对抽取的上游源码做全仓格式化 |
| 格式化工具 | `.editorconfig` 已规定 UTF-8、LF、4 空格；`package.json` 没有 format/lint 脚本，也未发现 Prettier/ESLint/Biome 配置 | 先定范围和规则，再做分批机械修改及 CI 检查 |
| Shader | `docs/manual/shadertoy.md`、`debugging-glsl.md` 均标 N/A；已有内建 effect 与材质参数示例，尚无经验证的“用户提供 GLSL → 编译 → 材质绑定 → 上屏”示例。`EffectAsset.register` 是待验证候选路径 | 先做可行性探针。可用则补完整 Shader 开发示例；不可用则立最小受支持入口任务，不能仅加一段无法运行的代码 |

上述数值是仓库快照，不是本计划重新跑出的当期验证结果。开工时须重新生成或只读核对；覆盖报告脚本会写正典文件，负控和试验运行应写仓库外临时路径或副本。

## 2. 目标与边界

1. 建立“Public API → 单点示例 → 组合场景 → 运行证据 → 文档”的可追踪矩阵，优先补 Core/Important 的真实使用路径及失败路径。
2. 交付五个经典游戏场景和一个应用场景，覆盖从启动、交互、状态变化、资源释放到复入的完整链路。
3. 固定 Code First 脚本组件开发流程、示例目录结构和代码风格，并使新示例自动遵循。
4. 交付可运行、可验证的自定义 Shader 最小示例；若底层缺口阻断，先给出实测结论、接口设计与实施次序。

不把 Feature Regression 遗留的全量 feature 回归、Advanced 8,060 单元逐项穷举、WebGPU 全平台等价性纳入本轮。不得降低现有 API 覆盖门槛或通过改 `coverageRequired` 缩小分母；确有分类错误时单列证据和评审记录。

## 3. 执行批次

### G0 — 基线与覆盖诊断（先行）

**任务**

- 记录 HEAD、工作区改动、58 例清单、现有测试/浏览器证据及构建指纹。开工前复核 `docs/api-coverage-report.json` 是否与当前示例和构建匹配；不得把 stale 例计为已覆盖。
- 从 `docs/example-api-inventory.json` 按模块与 tier 提取未 verified 的 `coverageRequired` 单元，排出 Top 20 组合路径。每项标明：调用链、正常结果、边界/错误、现有示例、缺少的 validator、浏览器/后端约束、预计成本。
- 盘点 `examples/`、`docs/manual/examples/` 与 Recipes 的重复或断链；把“已有但未进 Gallery/coverage”的内容单独标记，避免重复建设。

**交付**：`docs/reference/api-scenario-gap-matrix.md`（含稳定 API ID 和优先级）、基线记录。**退出条件**：Top 20 均有证据定位和实施去向，过期证据被明确隔离。

### G1 — 接口组合场景与故障路径（P0）

按业务动作组织示例，不按“一个类一个页面”机械铺量。首批建议如下；每例都需 `example.json` 的效果契约、API claim/evidence、独立状态断言和截图或帧缓冲验证。

| 场景 | 必须穿透的接口链 | 关键断言 |
| --- | --- | --- |
| 动态场景切换 | `createAirApp` → `Scene` / `Node` / `Component` → `run(scene)` → 销毁 → 再进入 | 旧节点不再更新，事件监听和资源不残留，新场景可见 |
| 模型角色交互 | glTF 加载 → 实例化两份 → 独立动画 → 点击/射线选择 → 材质反馈 → 销毁一份 | 两实例状态隔离，释放其一不影响另一份 |
| 2D/3D 物理交互 | 输入 → 刚体/碰撞 → 事件 → UI 状态 → 重置 | 后端、接触/离开、重置与降级行为可复现 |
| UI + 资源加载 | UI 控件 → 异步加载/失败 → 进度/错误 → 重试 → 释放 | 快速重复点击、取消或切场景时无悬空回调 |
| 渲染组合 | 相机/灯光 → 材质/纹理 → 后处理或渲染目标 → resize | 画面真实变化；WebGL1/2 能力不足时有明确结果 |

若某条链的公开接口尚不可用，先登记最小功能缺口、复现用例和修复依赖，再继续示例。优先修跨场景共用的入口或生命周期缺陷；不为通过示例新增平行包装 API。

**交付**：首批 5 个可运行组合示例及覆盖矩阵回填。**退出条件**：每例同时有正向结果、至少一个边界/失败断言，Browser Matrix 对适用浏览器通过，API `verified` 增量可逐项复核。

### G2 — 经典游戏与应用场景（P1，可在 G1 骨架稳定后开展）

| 作品 | 最小完整循环 | 覆盖重点 |
| --- | --- | --- |
| 经典游戏：俯视角收集与躲避 | 开始/暂停/重开、移动、拾取、敌人或障碍、计分、胜负、音效与 HUD | 输入、组件生命周期、碰撞/动画、UI、音频、对象复用与场景重置。复用手册 `manual-mini-game` 的有效部分，升级为 Gallery 可验收示例；若选用物理，标明真实后端，不把距离判断称为物理碰撞 |
| 经典游戏：俄罗斯方块 | 方块生成、移动/旋转、落下与锁定、消行计分、加速、游戏结束与重开 | 键盘/触控输入、固定步长逻辑、网格状态与渲染分离、UI 更新；验证墙踢/边界、连续消行和暂停恢复 |
| 经典游戏：消消乐 | 交换相邻元素、三连判定、消除下落、补牌连锁、步数或时间目标、胜负与重开 | 指针交互、动画队列、确定性随机种子、状态锁与 UI；验证无效交换回滚、连锁计分、动画中重复输入 |
| 经典游戏：坦克大战 | 玩家移动/射击、障碍与敌人、命中/受伤、关卡胜负、重开 | 2D 碰撞或明确的网格碰撞、弹丸对象池、敌人状态、音效与资源回收；验证弹丸销毁、障碍阻挡和同时命中 |
| 经典游戏：魂斗罗（横版动作） | 横向卷屏、移动跳跃、射击、敌人生成、受伤/无敌帧、关卡终点、死亡与重开 | 角色控制、相机跟随、动画状态、碰撞层、投射物与对象池、音效/UI；验证落地/跳跃边界、镜头边界、场景复入。使用原创角色和素材，保留经典玩法结构 |
| 应用：交互式 3D 产品查看器 | 加载/失败重试、旋转缩放、部件选中、材质切换、信息面板、截图、模型替换 | glTF、相机、拾取、材质实例、异步状态、资源释放、尺寸响应及 DevTools 诊断 |

六个场景均提供源码入口、运行命令、用户操作说明、确定性自动演示模式、状态探针及资源生命周期断言。每个游戏须能从开局实际到达胜/负状态并重开；产品查看器须能完成加载、替换和失败重试。完成度不能只凭首帧截图判定。

### G3 — 开发范式与代码格式（P1）

**范式文档**：新增一篇“脚本组件开发流程”，从创建 `Component` 类、字段/依赖、`onLoad` / `onEnable` / `start` / `update` / `onDisable` / `onDestroy` 的职责，到输入事件订阅与退订、异步任务取消、材质实例与资产所有权、热重载/场景切换、调试与发布。只写经当前 SDK 可运行验证的用法；用一个完整示例贯穿，不复制多个互相漂移的片段。

**项目结构**：给出 `index.html`、`src/main.ts`、`src/components/*.ts`、`assets/`、`example.json` 的推荐布局；定义 `main.ts` 只负责启动与组装，交互放组件，资源/状态服务独立。迁移现有示例采用“新增与触达时迁移”，先挑 `starter`、`hello-cube`、一个复合场景作样板，再按风险分批。保留已冻结示例的规格与证据映射，迁移后刷新源码行号和指纹。

**格式化**：在 `.editorconfig` 基础上选定 TypeScript/JavaScript/JSON/Markdown 的格式工具和固定版本，配置 `format`、`format:check`。首批只覆盖 `examples/`、`docs/manual/examples/`、`tools` 中自有新代码与相关文档；`src/cocos/**` 等逐字节跟踪的上游抽取文件排除。先做 dry run 与变更量审查，避免纯格式改动淹没行为改动；后续把检查接入 CI。制定 import 顺序、命名、单语句单行和生命周期清理规范。

**退出条件**：样板项目按文档从空目录可运行；组件卸载/重入测试通过；范围内新改文件格式检查通过，`verify:file-map` 不因格式化破坏上游映射。

### G4 — Shader 开发路线与示例（P0 探针，P1 交付）

1. **验证入口**：用最小 `EffectAsset`/effect 资源定义顶点与片元源码，确认注册、`Material.initialize` 或 `effectAsset` 绑定、uniform 更新、WebGL2 上屏；再测 WebGL1 降级。记录编译/链接错误的可读路径，以及资源销毁和重复注册行为。探针写在隔离示例，不先宣称 SDK 支持。
2. **若路径可用**：交付 `shader-custom-gradient`（最小顶点/片元、颜色/时间 uniform）和 `shader-dissolve` 或 UV 动画（贴图、动画、交互）两级示例；补 effect 资源结构、参数绑定、材质实例、兼容性与调试文档，并纳入 Gallery 和浏览器验证。
3. **若路径不可用**：明确阻断点（资源格式、编译接线、导出面或错误回传），提出最小公开接口及向后兼容方案，先完成接口和测试，再交付同一套示例。内建材质 `setProperty` 演示可作过渡，但不能代替“用户自写 Shader”验收。

**退出条件**：至少一个用户编写的 fragment 源码在浏览器实际编译并改变像素；参数变化可由帧差/读回验证；故意错误能得到可定位的诊断；支持与不支持的后端结果明确。届时更新 `docs/manual/shadertoy.md`、`debugging-glsl.md` 的状态，不再让 N/A 文档与新能力矛盾。

## 4. 门禁、顺序与工作量

| 阶段 | 依赖 | 估算 | 核验 |
| --- | --- | --- | --- |
| G0 诊断 | 无 | 1–2 人日 | 清单、证据有效性、Top 20 差距复核 |
| G4 Shader 探针 | G0 | 1–2 人日 | 真机/浏览器最小像素结果或可复现阻断证据 |
| G1 组合场景 | G0 | 5–9 人日 | 5 例的功能、交互、生命周期与 API proof |
| G3 范式/格式 | G0，样板依赖 G1 首例 | 3–5 人日 | 文档实跑、format check、上游映射 |
| G2 游戏/应用 | G1 核心链路 | 18–30 人日 | 五个游戏与一个应用的完整循环、跨浏览器与资源重入；按俄罗斯方块/消消乐 → 坦克大战 → 魂斗罗逐步扩展输入、碰撞和镜头能力 |
| G4 Shader 正式交付 | 探针结果 | 2–6 人日；若需 SDK 入口另估 | 两级示例、文档与编译失败诊断 |

估算为单人实施量，Shader 入口若需改底层，G4 需在探针后重新估时。G1 和 G3 可按不冲突文件推进，但不得并发改同一示例的规格或正典证据。每阶段修改后按影响范围运行 `npm run typecheck`、相关 Jest、构建、示例规格/证据检查与浏览器验证；只有需要发布判定时才跑完整门禁。报告分别列出 PASS、FAIL、NOT_RUN、证据过期，不以旧快照代替新结果。

## 6. 风险与决策点

- **覆盖率规模**：现有 Core/Important 缺口远超 5 个组合示例可填满。本轮交付的是可复用场景体系和优先级最高的一批；若目标是达到 Core 100% / Important 90%，需在 G0 后另开批次预算，不能宣称本轮已达标。
- **旧文档漂移**：手册 `game.md`、`shadertoy.md` 的结论与现有 Feature Regression feature 面可能跨版本；引用时以当前可运行验证为准，更新状态须附新证据。
- **Shader 资源格式**：`EffectAsset.register` 具备线索但无用户侧成功样例。探针结果决定实施分支，不先设计过大的 `ShaderMaterial` 新抽象。
- **工作区并发改动**：起草时 `docs/evidence/v11-gallery-artifact.json` 与 `examples/gltf-catalog/main.js` 已有未提交修改；后续实施需先复查这些文件，不能覆盖或据其变动推断本计划的完成情况。
