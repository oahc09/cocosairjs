# Cocos AIR 高质量互动内容：功能补全任务书

创建：2026-10-25。状态见[执行台账](../ledgers/vibe-content-capabilities.md)。

## 来源与目标

依据用户提供的 2026-10-18—25 Vibe Coding 作品周报，补齐大规模动态内容、精细程序化物件、环境表现和可复用交互功能。周报属于需求输入；作品数量、粒子数、帧率、物理准确性和模型归属不作为本仓库的实测结论。

现有 HDR/Bloom/ACES/Reinhard、RenderTarget、基础实例化、glTF、物理、输入与生命周期能力作为依赖复用，不重复开发平行引擎。新增装配接口优先放在 `src/air/`；仅在实际阻塞时最小修改抽取源码并同步上游映射。默认 WebGL2，实验 WebGPU 不作为默认能力的隐式前置条件。

## 实施与验证

1. F01–F04：动态批次 → 粒子 → 形态/力场闭环。
2. F05–F08、F15：精细物件、物理材质与透射闭环。
3. F09–F12、F18：环境与可探索世界。
4. F13–F14、F16–F17：控制、音画与跨界面交互。

每项分别记录源码/API、CPU 测试、构建/声明、真实浏览器画面/行为及释放证据。字段写入成功、历史报告或计划完成不等于当前运行验收。以必要的定向回归为主，不增加无关测试；源字节变化后重新采集受影响证据。不得据周报数字直接承诺 6K/60K/260K 的固定帧率。

## F01 首批设计与范围

- 一个批次复用原生 Node、Mesh、Material、renderer/model 和 GFX，不创建平行场景系统。
- 支持索引网格、实例变换/颜色、实际实例数、范围提交、显式扩容、聚合 bounds、射线选择及幂等释放。
- 先做可审查的独立批次，避免用 N 个 Node 包装器冒充高密度批次。材质必须明确声明匹配的实例属性；不静默改写任意用户 shader。
- 先以 CPU 数据合同与小型实际实例化场景验证，再测较大规模。通用粒子、GPU 力场和大型世界分别属于后续任务。
- 当前授权不包含提交、push、发布或修改已有证据状态。

## F03 首批设计与范围

- 点集使用相同数量和稳定索引的 flat Float32 位置/线性 RGB；图像按 alpha、网格按三角形面积采样，文字通过字体就绪后的 canvas 光栅接入，不读取在线资产。
- 渲染复用 F01 的原生实例流，所有形态预先上传 GPU 纹理；改变形态进度只更新 uniform，不把每帧 CPU 插值矩阵包装成 GPU 形变。
- 每点跨所有形态的包围 envelope 映射到实例矩阵，纹理记录归一化局部偏移；聚合 bounds 保守覆盖源/目标和图元尺寸。不得沿用单一形态的 bounds 导致中途消失。
- 先提供固定数量的点/体素与显式形态对、进度控制；业务使用现有时钟/动画驱动。此阶段不新增播放器，不宣称透明排序、骨骼 Morph、GPU picking 或反馈力场。
- 验证 CPU 采样/非法输入，再验证 GPU 关键形态和中间进度像素、bounds/父变换、实际 draw/实例数、上传字节、设备限制和资源释放。规模只记录当前设备的实测，不承诺周报中的帧率。
