结论：先核对当前 HDR/LDR 模式下的光照单位与曝光，再检查真正生效的主方向光及全局、灯光、投射和接收四层阴影开关；仅提高灯光数值不能保证亮度或阴影正确。本回答是冻结文档诊断，未检查或运行当前场景。

1. **亮度与单位**：`DirectionalLight.illuminance` 使用 Lux（lx）；默认 HDR 值为 `65000`，LDR 槽的默认值为 `65000 * standardExposureValue`。局部 `PointLight` / `SphereLight` / `SpotLight` 区分 `luminance` 与 `luminousFlux`；`nt2lm(size) = 4 * PI * PI * size * size`，HDR 光通量赋值先除以 `nt2lm(size)` 转成亮度。Point 的换算使用 size=1，Sphere/Spot 使用各自 `_size`。不要直接互换这些属性的数值。依据：`skills/cocosair-rendering/references/lighting-units.md` 的 “DirectionalLight illuminance” 和 “Local light ... luminous units”。
2. **曝光与颜色**：HDR 下方向光和 `Ambient.skyIllum` 乘 `camera.exposure`；局部灯的亮度额外乘 `standardLightMeterScale = 10000`，此缩放同时适用于 Point/Sphere/Spot。LDR 使用对应 LDR 槽值，不再乘 exposure。`standardExposureValue = 1 / 38400`。检查模式、所写槽和曝光是否匹配；`Light.color` 应传 `Color`，组件 RGB 通道是 0..255，不能误当 0..1。依据：`skills/cocosair-rendering/references/lighting-units.md` 的 “Conversion written into the UBO” 和 “Light component surface AIR exposes”。
3. **主光是否选对**：默认 legacy forward 的普通方向光只有一个有效 `renderScene.mainLight`，第二个方向光不会增加独立补光，添加时会产生 `[AIR_W_DIRECTIONAL_LIGHT_LIMIT]` 警告。用 `inspectAirDirectionalLights(scene)` 查看 `mainLight`、`lights[].effective`、`ordinaryDirectionalCapacity: 1`，并确认预期的灯就是有效主光；场景无 native render scene 时会返回 unavailable。只有主方向光进入其方向光阴影路径。依据：`skills/cocosair-rendering/references/lighting-units.md` 的 “Legacy forward mainLight limitation” 及 `skills/cocosair-rendering/references/shadow-matrix.md` 的 “Concrete silent-miss symptoms”。
4. **阴影支持条件**：默认 WebGL2 legacy 管线中，主 `DirectionalLight` 支持 ShadowMap 的 fixed-area / CSM；Planar 仅沿主光方向投到一个平面。Spot 支持打开 `shadowEnabled` 的 ShadowMap，但不作为 Planar 投影源；Point 不支持阴影生成，Sphere 无默认阴影路径，RangedDirectional 无本矩阵的默认主光阴影契约，Ambient 不投影。不能用 Spot 的结果证明 Point 阴影。依据：`skills/cocosair-rendering/references/shadow-matrix.md` 的 “Support grid” 和 “Documented workarounds”。
5. **必查开关**：全局 `shadows.enabled` 必须为 true，`shadows.type` 必须选择 `ShadowType.ShadowMap`；方向光的 `light.shadowEnabled` 必须为 true；投射物 `shadowCastingMode = MeshRenderer.ShadowCastingMode.ON`，接收物 `receiveShadow` 必须启用。全局和方向光阴影默认均关闭；全局关闭或类型不是 ShadowMap 时 ShadowFlow 直接返回，没有阴影不一定有警告。`ShadowType.Planar = 0`、`ShadowMap = 1`，没有公开 `None`/`Inherit` 枚举，不要混淆枚举值和宏值。依据：`skills/cocosair-rendering/SKILL.md` 的 “Contracts” 和 `skills/cocosair-rendering/references/shadow-matrix.md` 的 “ShadowFlow gate”、“Enum ordinals” 及 “Concrete silent-miss symptoms”。
6. **开关正确仍缺阴影**：检查模型是否有有效 bounds（无效 bounds 会被方向光阴影剔除队列跳过），以及阴影覆盖范围。方向光 `shadowFixedArea` 决定固定范围路径；核对 `shadowNear`、`shadowFar`、`shadowOrthoSize` 或 CSM 的 `shadowDistance`、`csmLevel` 和平台 `csmSupported`；CSM 要求 level > 1 且受支持。再检查 `shadowBias`、`shadowNormalBias` 是否使阴影偏离，`shadowSaturation`、PCF 和贴图大小是否符合预期。这些方向光范围/CSM字段不能套给 Point/Sphere 或 Spot；Spot 只有 `shadowEnabled`、`shadowPcf`、`shadowBias`、`shadowNormalBias` 四项。组件的 render-scene light 尚未创建时，setter 只保存私有字段，没有立即管线效果。依据：`skills/cocosair-rendering/references/shadow-matrix.md` 的 “DirectionalLight shadow fields”、“SpotLight shadow fields”、“Fields ignored by the shipped pipeline” 和 “Concrete silent-miss symptoms”。

验收边界：文档中的主光 ShadowMap 像素证据只覆盖历史 `examples/campfire-night/` 固定场景及其指纹；Spot 本轮未单独采样，Planar 虽有原生路径但未取得可判定 ROI 像素变化。相应契约标识为 `AIR_SHADOW_POINT_UNSUPPORTED`、`AIR_SHADOW_SPOT_RUNTIME_NOT_SAMPLED`、`AIR_SHADOW_PLANAR_ROI_NOT_VERIFIED`。配置成功、声明或 bundle 可达都不等于当前场景浏览器 PASS，仍需实看阴影/像素；Planar 应记录投影范围和接收平面。依据：`skills/cocosair-rendering/references/shadow-matrix.md` 的 “Documented workarounds” 和 “Bundle reachability”，以及 `skills/cocosair-rendering/SKILL.md` 的 “Contracts”。
