# Cocos Air V0.3 — Asset Integration & Runtime Verification 任务计划书

> 与 V0.1 / V0.2 连续演进。修订日期：2026-09-12。
> 状态：本版范围已实施并验证（2026-09-12）。V0.2 经前置审查补修；外部 glTF/GLB 已交付子集完成使用侧集成，其他格式覆盖仍由对应任务负责。见 [验收记录](../docs/11-v03-verification.md)。
> 合并修订：纳入补充计划的资源关系分析、资源索引说明、Code First 组装、资源检查与角色示例；glTF/GLB 加载、解析、导入和转换仍由外部任务负责。

## 0. 版本关系

| 版本/任务 | 职责 | 与本版关系 |
|---|---|---|
| V0.1 | 独立 Web/TS 引擎、构建、启动和基础示例 | 保留已成立能力 |
| V0.2 | Code First helper、类型声明、开发反馈链 | 使用最终验收版本，不重复实施 |
| 独立 glTF/GLB 任务 | 模型加载及其配套实现 | 接口与支持范围以该任务交付为准 |
| V0.3 | 资源关系与索引、Code First 组装、资源检查、运行时回归和静态验证 | 消费既有成果，不建立另一条加载链 |

本次用户明确调整优先于 V0.2 计划书第 40 节的暂定方向。V0.2 原计划保持不变，执行 V0.3 时以本修订的范围为准。

合并来源：用户提供的下载文件《Cocos Air V0.3 — Standalone Asset Pipeline（V0.1-V0.2连续版）任务计划书.md》。来源文件保持原样；章节合并位置与冲突处理见第 12 节。

```text
Source Asset
    → 外部资源加载/生产任务（实现方式以交付为准）
    → 原 Cocos Runtime 数据
    → V0.3 Code First Assembly / Inspect / Validate
    → Cocos Air Runtime
    → Browser
```

资源生产、代码创建、运行时渲染与 Web 开发体验构成整体闭环；其完成状态由各任务真实交付共同证明，不能仅由 V0.3 回归结果推定。

## 2. 范围与协作边界

### 本版保留

- 资源生产结果与 Runtime 必需数据的关系分析，区分源数据、生成数据与编辑器附属数据。
- 沿用现有资源索引与依赖描述，补充 inspect/validate 能力及 Code First 组装示例。
- V0.2 完成后的公共入口、类型及既有示例回归。
- 已有原 Cocos 对象的材质、动画使用与生命周期验证。
- 普通静态服务下的示例运行、相对路径与构建产物验证。
- glTF/GLB 任务已交付时，按其文档进行使用侧集成验证。
- 对本版实际复现的集成问题做最小修复，补充证据与使用文档。

### 本版移除

- glTF/GLB reader、loader、importer 及格式兼容性实现。
- Air GLB Profile、accessor 解码、坐标转换、材质/骨骼/动画转换算法。
- 自定义 manifest/model.bin 资产包、schema 和格式版本体系。
- `tools/import/`、导入 CLI、确定性导出及导出校验命令。
- 新增 `loadModelAsync()`、`LoadedModel` 或另一套模型加载/释放协议。
- 因上述解析/转换管线而新增的目录、测试、排期及验收门禁；使用侧示例与资源检查按下文独立安排。

glTF/GLB 任务负责自己的格式支持、错误行为、返回对象、缓存和释放约定。本版不替它设定支持子集、不修改其工作文件、不自动向它派单。

若使用侧发现问题，先判定归属：加载/解析/转换缺陷交回对应任务；示例调用错误在本版修复；共享引擎缺陷先记录根因、影响和文件归属，再协调最小修改，避免两个任务并发修复同一位置。

## 3. 继承约束

1. 保持单仓库及现有一级目录，不新增产品层或迁移技术栈。
2. 原 Cocos API 继续作为主 API，不新增 AirNode/AirMaterial/AirAnimation。
3. 保留 V0.2 公共接口、构建命令、类型声明流程与产物名称。
4. 不为验证需求新增公共运行时诊断接口；测试控制入口留在 test/examples/tools。
5. 保留上游布局、版权及映射，不自动同步 cocos4；实际引擎修改按既有机制记录。
6. 未交接前不编辑其他 Agent 的工作文件。编辑前重新检查目标差异并保留并发改动。
7. 用户已授权先审查修复 V0.2，再实施本计划；不自动提交、发布或远端部署。

目录落位规则：

| 内容 | 位置 | 约束 |
|---|---|---|
| 运行时修复或必要薄适配 | `src/air/`，资源职责明确时才使用 `src/air/assets/` | 不预建目录、不迁移 app.ts/bootstrap.ts，不引入新 Asset Format |
| 开发期资源检查 | `tools/verify/` 或已有等价工具 | 不进入浏览器运行时；已有入口先复用 |
| Code First 组装示例 | `examples/shared/`、条件性的 `examples/character-runtime/` | 不新增 createModel/AirModel 公共抽象 |
| 数据与行为验证 | `test/unit/`、`test/smoke/` | 不平行新增 asset/importer/runtime 测试体系 |

外部任务若已有 `tools/import/`，保留其职责与所有权；本版不要求创建 gltf/texture/compiler 子树。现有 `tools/dev/` 等实际目录继续沿用。

保留 V0.2 开发反馈链：示例修改不触发无关引擎全量重建，Engine/Air 修改沿用已有 build/reload。若外部任务提供 Asset Build，资源修改按其命令更新后进入已有刷新流程；本版不强制新增自动导入 watch。

退出条件：本版需要的 V0.2 基础已交接，验证对象和已知限制明确。未交接部分暂缓，继续不依赖它的文档与证据整理。

### T0-A — 资源生产关系分析与索引约定

承接补充计划 Phase 1/2。先读现有资源、加载实现及已提供的导入说明，不立即重写 Creator Import Pipeline，也不以安装 Creator 为前提。

对 Mesh、Material、Texture、Skeleton、AnimationClip 建表回答：

1. 哪些内容来自源文件，哪些由资源生产工具生成？
2. 哪些内容是当前 Runtime 必需，分别由谁创建和持有？
3. 哪些依赖需要随示例部署，如何从公开入口定位？
4. 哪些属于 Editor/Prefab 附属信息，Code First 使用可以不消费？

每个判断附实际文件、字段或接口依据。没有 Creator 源码或导入记录时标为未知，不能从运行时样例倒推完整生产实现。

资源索引仅用于说明和查找已有资源，不复制 AssetDB，不建立 Editor UUID 管理。优先采用外部任务已有 manifest、URL/路径约定或返回资源集合；无需 manifest 的直接加载方案不强制增加 manifest。

记录模型名、Mesh/Material/Texture 引用、Skeleton 与 clip 对应关系以及所有权。补充计划中的 robot.mesh/robot.material 等仅视为示意，不规定真实文件扩展名；不新增二进制格式、schema 版本体系或加载器。

退出条件：已交付资源的数据与依赖关系可追溯；外部未交付部分标为待交接，不阻断已知部分分析。

## 5. Task T1 — 运行时行为与生命周期回归

复用既有样例及已交付测试资源，不新建模型解析或转换流程。

| 对象 | 检查内容 | 证据要求 |
|---|---|---|
| 材质/纹理 | 已支持属性修改、纹理引用、实际渲染结果 | 属性变化对应可见画面变化；赋值不报错不足以通过 |
| 场景/节点 | 添加、移除、销毁及再次运行的既有支持行为 | 对照最终 API 合同，不自动要求 app 新增 destroy/stop |
| 动画 | 对已有可用 clip 检查播放、暂停、恢复、切换 | 原 Animation API 与画面/固定时间采样；不实现 clip 转换 |
| 多实例 | 在现有 API 支持的实例化方式下检查状态隔离 | 一份对象的操作不意外改变另一份 |
| 释放 | 按现有所有权规则释放本实例资源 | 不破坏共享或 builtin 资源；不强制新建 dispose API |

资源共享、缓存与释放以已交付实现的合同为准。若合同缺失，先由对应任务补齐，不在 V0.3 擅自重定义。

对于没有可用 clip 或没有相应能力承诺的路径，记录未验证原因；不以新增 loader、采样器或转换算法填补。已声明支持而实际失败的路径必须记录失败，不能归为不适用。

退出条件：约定的运行时行为完成验证，本版归属的问题已修复，其他任务归属的问题有明确记录。

## 6. Task T2 — 外部模型功能的使用侧集成（条件项）

触发条件：glTF/GLB 任务已提供可使用版本、公共接口说明、支持范围、示例资源与生命周期约定。当前不假设这些信息已经存在。

仅执行：

1. 优先运行该任务现有示例，按其公开入口使用，不访问内部路径。
2. 确认返回的场景/资源能够与 createAirApp、原 Cocos API 协同。
3. 对其已声明支持的材质和动画做代表性回归，复用其测试资产和预期值。
4. 检查业务使用文档是否完整，记录集成问题和归属。

不重复其格式兼容测试矩阵，不新建资产格式、loader wrapper、独立 CLI 或导入示例体系。沿用 `loadAssetAsync()` 的最终职责；若外部任务采用其他公开入口，直接使用其交付接口，不为统一名称强制扩展 overload。

若外部任务尚未交付，标记“外部集成未执行”，不阻断本版独立回归；不得因此宣称 glTF/GLB 已集成或验证完成。发布说明必须明确这一状态。

### T2-A — Code First Model Assembly 与角色示例

承接补充计划 Phase 6/8。使用原 `Node`、`MeshRenderer`、`SkinnedMeshRenderer`、`Animation` 组装；已返回完整节点树时直接使用，不重复拆解重建。

V0.2 的 `buildSkeletonTree()` / `restoreBindPose()` 仅在交付数据符合其约定时复用，不能盲目覆盖源姿态。通用演示代码留在 `examples/shared/`，不提升为新的模型公共 API。

优先完善外部任务已有角色示例；确实没有覆盖组合使用的示例时，再新增 `examples/character-runtime/`，展示其已支持的 Mesh、Material、Texture、Skeleton 和 AnimationClip 协同。按实际能力提供播放控制、错误提示及资源释放说明。

`examples/asset-pipeline/` 仅在外部任务已有可运行生产链且没有等价演示时复用或补充，不作为本版固定交付。不得为完成示例名而新增导入器。

退出条件：已交付能力在 Code First 示例中可复现，资源来源与限制明确；未提供的能力不伪造演示，不要求额外关节数或 clip 数量。

### T2-B — 资源 Inspect / Validate

承接补充计划 Phase 7/9 的使用侧检查，作用于已交付的 Runtime 资源、索引或返回对象，不解析 glTF/GLB 源文件。

| 能力 | 检查内容 | 验证 |
|---|---|---|
| Inspect | 列出可见的 Mesh、Material、Texture、Skeleton、AnimationClip 与引用关系 | 与已知样例的资源清单对照 |
| Validate | 缺失依赖、无效引用、类型不符、动画目标无法绑定 | 正常用例和针对性损坏用例验证诊断 |

先复用现有检查器；缺失时在 `tools/verify/` 增量增加最小检查入口。可离线读取的数据由 Node 检查；只能运行时获得的信息通过现有 smoke/browser 流程收集，不引入自定义序列化来迁就检查器。

诊断包含资源标识、引用位置与原因；未暴露的数据标为“无法检查”，不能推定通过。命令行验证发现错误返回非零退出码，不能只输出日志后成功退出。

补充计划的 `cocosair asset inspect` / `cocosair asset validate` 表示能力意图，当前不保证存在这些命令，也不要求新增顶层 CLI 产品。实际入口在交接后确定并写入文档。`cocosair asset build` 归属外部资源生产任务，本版不实现。

已有可用资源先完成最小 Inspect/Validate；外部模型专属检查随其交付扩展。测试继续放入现有 unit/smoke 结构，不复制 importer 测试。

- 使用真实 TypeScript consumer 验证公共入口与声明，不再建立一套声明生成流程。

沿用项目实际强制检查，按本版改动执行：

```bash
npm run typecheck
npm run build
npm run build:min
npm run verify:web-only
npm test
```

若 V0.2 的最终流程另有必检项，继续保留。只改文档时做内容、引用及 diff 检查；实际修改代码或画面时运行对应行为验证。

退出条件：独立静态示例与公共入口验证通过，本版变动所需的既有检查通过。

## 10. 执行顺序与交付

顺序：T0 交接与 T0-A 资源分析 → T1 运行时回归及已有资源的 T2-B 检查 → T3 静态验证 → T4 文档。T2/T2-A 及外部资源专属检查在外部成果可用后插入，不阻塞独立工作。

旧版围绕 importer 的 10.5–17 人日估算撤销。新估算在 T0 明确未覆盖行为与实际问题后给出，避免把其他任务工期重复计入。

默认单 Agent 执行，不自动派生子任务。对共享引擎、package.json、lockfile 和公共导出的修改需要明确写入归属。

完成条件：

1. 本版必需验收项通过，本版归属的失败已解决。
2. 外部集成单独标记已验证、未执行或失败，不混入整体完成结论。
3. 文档明确前序遗留问题；影响必需项的未解决失败不能以外部依赖为由标记通过。
4. 交付范围内 diff、验证证据与使用文档；不自动提交、发布或部署。

范围外继续包括 MCP、编辑器、物理/UI、WebGPU 迁移、动画状态机/重定向、全量 PBR、monorepo 化与上游同步。

## 11. Deviations

- 原因：用户明确 glTF/GLB 加载功能已有独立任务处理，要求从本计划移除。
- 影响：撤销原计划的解析/导入、资产包、CLI、加载 API、转换实现及相应验收与排期。
- 处理：本版不实施资源生产管线；合并补充计划后增加资源关系分析、索引说明、组装与检查能力，模型功能以外部交付为条件集成。
- 不变约束：V0.1/V0.2 连续性、原 Cocos API、单仓库结构、既有强制检查和并发修改保护。
