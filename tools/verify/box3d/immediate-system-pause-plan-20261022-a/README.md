## 1. Important source facts before implementation

1. **Setter notification alone is insufficient.** `PhysicsSystem.enable` and `autoSimulation` only guard then write their caches (`physics-system.ts:108-111,215-218`). `postUpdate` checks enable once, adds accumulated time, emits BEFORE_PHYSICS and unconditionally continues its tick loop (`401-430`). `step` delegates independently of enable (`494-497`). A BEFORE callback can therefore disable and still be followed by a native tick on this baseline.
2. **The real owner has no producer roster or pause reason yet.** `world-command-owner.ts:105-138` owns one logical queue, but imports/constructs no `Box3DCommandProducers`; its phase union has no System control transition (`75`). Its queue never enters the actual step consumer. The private producer primitive is separate. Therefore an empty actual-owner roster cannot demonstrate real hook suspension, continuous-handle disabling or target-lifetime acceptance.
3. **Queue pause preserves ownership, not native zero.** `command-queue.ts:454-462` clears pending records and changes phase; it does not revoke active/protected target ownership. Reduction later generates active idle-zero or protected paired-clear (`309-350`), and only committed protected operations retire the protected state (`430-434`). There is no reason to call `revokeTarget` on System pause. Native command replay writes both velocities for paired clear (`command_bridge.c:189-192,219-235`); merely clearing JS records cannot establish that native velocities became zero.
4. **A naive paused queue introduces a late native-allocation failure.** `registerBody` permits only ready (`command-queue.ts:223-229`). Actual `Box3DSharedBody` allocates/disables/configures a native body before `owner.adoptBody` (`shared-body.ts:223-246`); `adoptBody` then calls queue registration (`world-command-owner.ts:209-226`). Its constructor catch faults the world (`shared-body.ts:247-263`). Paused logical registration must be deliberately admitted for configuration-only bodies, or rejected before allocation. Leaving the late failure is not acceptable.
5. **Raw B0 failure handling is not a drop-in setter template.** B0 prepare/effect/commit can fail, notify, dispose and make the ticket terminal before throwing (`physics-state-observer.ts:440-455,486-500`). A naive catch calling raw `ticket.fail(error)` then throws a new terminal-ticket error (`440-442`), replacing the original. The material wrapper already checks terminal diagnostics before failing (`physics-material-transaction.ts:262-270`). Reuse that principle, not its material-only delegate registry.
6. **Disabled scene synchronization currently means preflight, not solver work.** `world.ts:432-436` runs body preflight and increments `sceneSyncCalls`; each body preflight checks scene consistency and reads native body state (`shared-body.ts:290-296`). Allow this specifically while System-paused. Do not call it zero-native-call work: native reads are present. It must not consume commands, invoke producers, write native motion or advance time.
7. **Bootstrap occurs before selector assignment.** Owner creation happens in World construction (`world.ts:90-95`); selector assigns the created world only after construction returns (`physics-selector.ts:145-163`). Existing owner binding validation intentionally occurs at a later safe point (`world-command-owner.ts:139-147`). A new registration must not fail normal bootstrap by asserting selector equality prematurely, nor assume every newly registered System is enabled.
8. **Game pause is not semantic owner pause.** `game.ts:591-608` controls the pacer and emits events; `step-clock.ts:101-121` deliberately pauses the game then calls `director.tick`. This increment must not subscribe GAME_PAUSE to the System reason or read `game.isPaused` as command admission. T12 remains separate.

## 2. Minimum private interface and file scope

The following names describe proposed responsibilities, not a public API or implementation promise. Keep all new helpers out of barrels, app options, `impl`, component properties and public callback contexts. No native pointer/token is passed through the control interface.

### Backend-neutral System control adapter

Suggested new file: `src/cocos/physics/framework/physics-system-control.ts`.

- `beginPhysicsSystemControl(system, operation)` accepts only `system-enable` or `system-auto-simulation` and returns undefined when unobserved. It wraps B0's ticket and preserves terminal first-failure identity. Its prepare takes a trusted reader returning the two private-cache booleans before/candidate; its commit reads the actual private cache independently. No native application delegate is needed.
- `registerPhysicsSystemControl(system, observer, executionAdmission)` returns one independently disposable private lease. Registration copies trusted callbacks once and binds the actual System, actual owner/world generation and registration identity. The adapter uses B0, but must not join the material-only `PhysicsMaterialTransactionRegistry`, which requires material candidates and a physical delegate.
- `readPhysicsSystemTickDisposition(system)` returns `unobserved`, `ready`, or `paused`. It throws for an observed faulted/closed or mismatched owner; those states must not silently become `paused`. This is a private identity-checked scheduling read, not a user-settable bypass.
- `assertPhysicsSystemManualStep(system)` rejects an observed paused/faulted/closed owner before retrieving a world or entering any command/body/candidate read. No-observer behavior remains original. World.step also calls its own owner execution guard, so direct internal world calls do not bypass the pause.
- Initial registration must receive genuine private System flags, even when enable was false before world construction. A small constructor-installed private snapshot closure, stored only in this adapter's WeakMap, is one workable solution: `PhysicsSystem` supplies a closure that reads `_enable/_autoSimulation` directly. Capture its identity without invoking public getters; consume it only at registration. Setters still build their own original-callsite snapshots. Do not discover initial state through user-overridable System getters. Validate live System/world binding at the existing delayed safe point.

No-observer paths keep their old assignment/value/evaluation semantics. The earliest `assertMutationAllowed` remains ahead of observer lookup, equality and validation. On observed paths, B0's system-control snapshot copier already rejects non-booleans (`191-196`). A same-value write still enters admission first; an idle same-value enable does not create a new pause/resume cycle.

### Prepared queue and producer transitions

Each participant exposes a private `preparePauseState(paused)` returning a receiver/identity-bound, one-use transition with `commit()`, `dispose()` and copied diagnostic facts. The token is tied to the exact queue/roster generation and preparation; it is not authorized by structural equality or a flag field.

- Prepare validates its local phase, no active copy/collection/candidate/lease, and terminal state; reserves its replacement data and freezes the entries that commit will touch. Preparing the second participant must not change the first participant's pending commands, target state or enabled handles.
- A local preparation reservation blocks every competing mutating method until terminal disposal. It is additional to existing phase/reading checks. It must reject caught reentry before any caller input is read, without poisoning an unrelated previously committed state.
- Queue commit on pause installs the prepared empty pending record array and paused phase. It does not alter body identities, active targets, protected-zero obligations, sequence, attemptId or completedTicks. Resume only installs ready phase. No reconstruction of discarded pending records on failure.
- Producer commit on pause disables the pre-reserved continuous entries and sets paused. Hook enabled flags are unchanged. Resume changes paused only. Commit must not call `#configuration`, owner admission, handle methods or public callbacks: those would reenter the already-held owner transition. The current producer `pause()` calls owner admission (`280-287,138-142`) and cannot be used blindly inside this commit.
- Commit does trusted metadata writes only. Reserve allocations before public enable-cache publication. Dispose releases only its own reservation; independently record failures. A prepared token must not release persistent target guards or replay an unknown cleanup.
- Existing standalone pause/resume may delegate to prepare/commit/finally, preserving their current primitive contract. Do not leave an alternative unprepared owner integration path.

### Actual owner and World

`world-command-owner.ts` gains a transient `system-control` phase plus an independent private `system-disabled` pause reason. Persistent pause is not the transient owner phase: idle+paused permits selected read/config/cleanup work, whereas material/collecting/solving/writeback/dispatch/control remains fenced. Store actual System flags and last transition facts separately from phase. Reserve a distinct future application/background reason, but do not wire it in B2.

Owner open uses the existing mutation/transform fence roster (System, bodies, components, ancestry, known assets). Preflight reserves every participant, verifies current copied flags and live world binding, and does no native work. Commit applies the reserved queue/roster metadata and records exact progress. Cleanup releases every reservation and temporary fence independently. Terminal teardown releases the System registration even if other cleanup fails; native body ownership remains governed by actual World teardown proof.

`world.ts` installs/releases the control observation alongside, not in place of, the material observation. Manual/automatic/direct world advancement uses owner execution admission. Scene-sync uses an explicit read/preflight-only admission that permits idle+System-paused without opening the command consumer. Existing material, query, cleanup and body configuration admissions must not accidentally become ordinary step admission.

**Recommended compatibility choice:** let queue `registerBody` run in ready or paused for trusted non-target logical ownership registration, after normal actual-owner configuration and before any simulation. This retains paused component assembly rather than introducing a new late failure. Target acquisition, submissions, producer registration/update/enable and cancelPending remain unpaused-only. This choice needs an actual-source paused-assembly control, not an assumption from the queue unit test. If the lead instead freezes no assembly while paused, move that rejection ahead of native creation.

## 3. Normal and failing transition order

For an observed enable setter:

1. Earliest System mutation guard, then create the control ticket. Do not short-circuit same-value assignments before admission.
2. Open all owner barriers; copy before/candidate flags exactly once from original private cache and the argument. Strictly validate both booleans. Reserve queue and, when actually present, producer transitions before any accepted-state change. Same-value transition reserves no pause effects but still validates phase/binding.
3. Write original private `_enable`; immediately record cache-written. No user event/callback occurs between this write and prepared participant commits.
4. Read actual flags and commit each trusted prepared participant, then the owner pause-reason metadata. Record participant entry and return separately. An unexpectedly throwing commit may have changed that participant; absence of return is not proof of no effect.
5. Dispose all temporary reservations/fences. Return only after successful cleanup; otherwise fault, preserve first error and retain unresolved cleanup facts.

For autoSimulation use the same guarded boolean/cached-state observation, but **never** prepare a pause transition. Neither queue, target/zero obligation nor producer configuration changes. The owner pause reason is determined by enable and future explicit lifecycle reasons, not autoSimulation.

| Initial state        | Requested transition                    | Result on normal return                                                                                                                      |
| -------------------- | --------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------- |
| idle, ready, enabled | enable=false                            | public false; System reason set; queue paused+pending empty; continuous disabled; hooks configured but not invokable; grants/zeros preserved |
| idle, System-paused  | enable=true                             | public true; only System reason removed; queue/roster eligible only if no other reason; discarded input absent; continuous still disabled    |
| idle, enabled        | autoSimulation=false                    | public manual scheduling; owner remains ready; all queue/target/producer state retained                                                      |
| idle, System-paused  | autoSimulation=false/true               | scheduling flag changes only; still paused; manual step still rejects                                                                        |
| active transaction   | any control write, including same value | earliest refusal; public/owner/queue/producer caches unchanged                                                                               |
| faulted or closed    | enable=true or manual step              | refuse; no resurrection, native retry or queue replay                                                                                        |

The System cache-first ordering is intentionally honest about unexpected partial failure, not advertised as impossible-to-fail native atomicity. All normal fallible admission is before it. If queue commit succeeds and producer commit fails, keep the now-empty queue; fault the owner/world and report actual public flags, queue commit fact and producer entry/return uncertainty. Never restore a guessed queue snapshot or run old callbacks again.

An error value `undefined`, `null`, `0`, `false` or `''` is still a primary failure. Use explicit `hasFailure` and identity-preserving rethrow, not truthiness or `error !== undefined`. If raw B0 has already closed, rethrow its diagnostics.error when hasFailure; do not invoke fail again. Later actual-cache readback, fault reporter or cleanup failures are secondary. Each release is attempted even if the preceding release throws. Keep cleanup attempted/succeeded/unresolved distinct. Do not use stringification as the only internal record of failure identity.

Do not rely on the frozen World's finally path as fixed: `world.ts:543-550` can replace an earlier error with a cleanup error, and frozen fault writes replace `failure` (`196-200`). The concurrent cleanup repair owns that correction; B2 must rebase its pattern on the repaired facts and rerun the relevant dual-failure controls.

## 4. Automatic loop and manual stepping

Keep the exact existing accumulator, fixed timestep and maxSubSteps. In the observed branch:

- At entry, disabled System retains scene-preflight-only behavior. It does not add deltaTime.
- With enabled+autoSimulation, reset the frame substep counter and add deltaTime as before, then emit BEFORE_PHYSICS.
- Immediately after that event, and before every actual fixed tick, read the registered owner's disposition. A nonthrowing pause skips/breaks tick execution without scene tick preparation, queue collection, solver or producer calls. Already-added time and backlog remain.
- AFTER_PHYSICS is still emitted on normal return, including a pause during BEFORE. A thrown BEFORE callback follows the original throwing path, does not reach AFTER and does not subtract time. A later pause/resume in the same BEFORE dispatch may restore eligibility, but the intervening pause has still cleared old commands.
- The successful tick's existing world step/event/sync-after sequence precedes accumulator subtraction and count increment. Failed/refused tick work does not deduct a phantom tick. Native completion followed by JS failure remains separate native-completion evidence, not permission to silently spend accumulator time or retry.
- Recheck before each next catch-up tick. A pause attempted inside protected collection/solver/writeback/dispatch rejects at entry even if caught; it must not become a partial mid-tick pause. A legitimate pause between fully completed ticks leaves the already-completed tick deducted and the remainder retained.
- Explicit System.step uses the same eventual one-tick consumer as automatic World.step, without synthesizing BEFORE/AFTER or resetting/decrementing the automatic accumulator. Paused owner rejects before native and command reads. `enable=true, autoSimulation=false` is the supported manual mode. Additional Cannon-style accumulator arguments still reject.

No current owner unified consumer exists. Wiring these guards is not permission to activate one. B2 may qualify its actual System scheduling subset first; producer/target end-to-end acceptance stays pending until an actual owner-connected roster and command consumer are installed under their separate scope.

## 5. Bounded implementation sequencing, without empty-roster overclaim

1. Preserve natural actual-source RED evidence for disabled manual step, BEFORE pause and observed strict booleans against an immutable baseline, before product implementation. The cases below have **not** run in this design.
2. Implement/review prepared queue and producer primitives independently, including preparation refusal and first-error cleanup. Their controls only establish logical JS behavior.
3. Wire actual System/World/owner pause with queue preparation, strict controls, direct step refusal, loop checkpoints and paused preflight/assembly. Keep the actual owner's current lack of live producer/target APIs explicit in diagnostics and reports. Do not install a fake producer owner with always-reject submit callbacks solely to claim integration.
4. When real producers become owned, they must be a mandatory coordinated participant, not an optional catch-and-ignore extension. No B2 claim for continuous/hook behavior until real producer handles can be exercised through their authoritative owner; isolated instantiated producers cannot fill that gap. Keep unified activation blocked regardless of the System subset's result.
5. Run new source-hash-bound controls against current repaired source, then current-WASM controls using existing artifacts/toolchain, without silently rebuilding frozen native inputs. Actual engine/current-WASM results remain distinct from browser/T12/formal cells.

This sequencing avoids silently expanding B2 into command consumption, persistent target grant budgeting or shared-material subscription integrity. The combined control contract is specified now; absence of a participant is recorded as not integrated, not success.

## 7. Exit criteria for the next narrow checkpoint

- Real observed System false pauses immediately; manual/direct World advancement rejects; normal BEFORE pause preserves accumulated time and AFTER behavior.
- Exact boolean and early-reentry behavior preserved, with no-observer compatibility control.
- Prepared transition has no normal fallible admission after cache publication, preserves first-error identity and truthfully faults partial/unknown commit; cleanup releases independent temporary resources without revoking grants.
- Paused scene preflight and paused assembly policy are pinned against actual engine source, not accidentally rejected by a broad owner gate.
- Active/protected target metadata is preserved, no native zero or physical equivalence is claimed from logical pause; unsupported producer/consumer/grant integration remains explicitly blocked.
- New control registration is independently released through repaired teardown, with the current material cleanup repair retained.
- Public staged/unified APIs remain false; shared-material integrity, actual producer/consumer connection, persistent grants and T12 remain separate open boundaries. All formal required cells remain NOT_RUN.
