Version: `gift-workshop-input-1` / `gift-workshop-abnormal-1`.

This is the missing M0/T32 specification supplement for the new reconstruction `rebuild-design-20261022-1`. It is not the recovered production1.2.5 configuration, an implementation, an executed input recording, or evidence that EX09 is playable. Every real behavior in the two JSON files is **NOT_RUN**. The existing README's description of the missing input/fixture specification is the earlier checkpoint; this supplement supplies that design without rewriting that checkpoint or changing its historical claims.

T32 can freeze the reviewed input schema, initialization differences, trigger procedures, observation assertions and bounded failure behavior without first obtaining T34's successful tick traces. T33 implements the public controls and diagnostics. T34 must establish real physical feasibility and retain actual positive and negative runs. ## Public input wire contract

Each packet contains exactly `protocolVersion`, `configVersion`, `layoutId`, `roundGeneration`, `inputGeneration`, `tick`, `seq`, `source`, `command` and `payload`. All fields are required. The envelope schema plus the selected command's payload schema form the complete packet schema. Unknown fields, unknown commands, non-finite numbers, out-of-range axes and non-safe integer identities are rejected before any side effect. Version/layout must match the effective profile loaded for this run. A derived anomaly cannot masquerade as the base normal profile.

`seq` is strictly increasing across the input session, including retry/replay. An identical duplicate receives its original acknowledgement without another action; an old nonduplicate or reused sequence with changed contents is rejected. `roundGeneration` identifies the currently loaded context and invalidates old scenes/rounds. `inputGeneration` is the fresh-input epoch: clear, pause/resume, recovery and scene changes invalidate queued movement from the previous epoch. Item and attempt generations are observed identities, never input arguments.

`tick` is the next fixed simulation step, `lastCompletedTick + 1`, not a render frame or arbitrary future time. A formal round begins before tick 1, with 10800 active ticks available. Multiple next-tick commands execute by sequence. The boundary lane may drain at that same boundary while paused or in READY/RESULT, without stepping physics or spending time. This is how resume and replay remain reachable when the simulator is stopped. Movement packets are rejected while paused. A pause barrier invalidates later queued old-epoch commands; the caller must read the acknowledgement before supplying fresh input. The explicit paused-boundary whitelist is in the JSON.

The ordered phases are input/safe requests, one actual physics step, immutable observation capture, real qualification, atomic shipment commit, shipping timeout, global timeout and safe destruction. A final order confirmed on the global deadline wins immediately; it does not wait for closing. The accepted submit step is elapsed shipping tick 1, so the 300th step is `submitTick + 299`. Complete genuine evidence at that step is processed before BLOCKED. This is an explicit counting convention, not an extra grace tick or a change to the 300-tick budget. Ordinary recovery charges exactly 300 remaining ticks at acceptance; zero or negative remainder locks timeout before another active step.

### Controls and action surface

- `set-axes`: finite world-space X/Y/Z intent in [-1, 1]. Horizontal diagonals normalize to a unit disk. Positive X is right, positive Z is front, positive Y is up. The command has no position/velocity argument.
- `key-edge`: W/S are -Z/+Z, A/D are -X/+X, Q/E are down/up. Opposing keys cancel. Space rising edge performs one attach/release; held/repeated down is not a new action. The same controller converts keys and touch/runner axes, with exactly one movement modality at a time.
- `attach-release`: genuine public attachment or release, with configured 0.03 m proximity and actual visibility/query checks. A miss does not move the item. The nearest valid geometric candidate wins, with logical item ID tie-breaking, not native index ordering.
- `submit-order`: one explicit validation attempt. A rejection explains its reason and counts once, not every stable tick or trigger; protocol-level rejection is not a business invalid-submit penalty. Acceptance creates an immutable snapshot, not a score or delivery.
- `pause`, `resume`, `clear-input`: clear axes, key latches, queued simulation commands and pending targets. Ordinary pause retains held constraint and pose and stops physics and business time. Background additionally pauses. Returning requires fresh explicit resume/input. Pointer release/cancel/capture loss clears sustained touch intent; keyboard key-up clears that key, and blur clears all.
- `recover-dropped`, `retry-order`, `clear-channel`: distinct explicit recovery requests for PACKING, BLOCKED and CLOSING. Their actual implementation may use the prescribed visible `recoveryReset` lifecycle, never arbitrary pose arguments. It must finish resource cleanup even when the penalty produces timeout.
- `start-round`, `enter-tutorial`, `replay-round`, `reset-round`, `exit-scene`: public start/tutorial/reset/navigation controls. Replay is accepted from RESULT. Reset while held is an explicit scene lifecycle replacement into fresh READY, not an undocumented transition added to the existing in-round state graph. Tutorial state never supplies formal-round receipts or results.
- `set-view`, `set-muted`: presentation only. A runner cannot impersonate a genuine user gesture to unlock browser audio.

The 1.2 m/s horizontal, 0.6 m/s vertical and 2 m/s² acceleration limits remain unchanged. The acceleration bound applies to the Euclidean change of intended velocity per fixed step, with independent horizontal and vertical caps also enforced. There is no rotation command. Safe target motion still requires all-sweep checks of the held compound, proper self-filtering and initial-overlap handling. Neither a numeric axis cap nor these specifications establish that runtime motion respects an obstacle.

No public command accepts an item pose, quaternion, velocity, clock, receipt, attempt ID, item generation, door angle or completed-order value. There is no completion/teleport/event-injection backdoor. The example packets are **syntax illustrations only**, not an accepted or successful trace. The five normal recipes name their matching frozen layout and specify real observation-based steering/stability/commit requirements, including completion by tick 9600 for the 1200-tick reserve. Successful tick-by-tick recordings remain T34 work.

## Initialization is not player input

A fixture setup is applied only before scene creation. It can select a declared variant, replace the initial placement of an existing item, add visible static geometry, or select the specified recovery-allocation diagnostic policy. It must preserve all twelve logical inventory instances, use ordinary dynamic item bodies, and start with no receipts, pending deliveries, stable counters or committed orders. It never supplies a fake active shipping transaction. Whole-round attempts start from the actual public start flow.

Resolve base config/layout plus the listed differences before any physics step, validate that resolved profile, and hash it. Every changed setup has an effective config version. The equal-mass theme and slow-door variants have their own explicit versions. Running changes to mass, shape, clock, pose or door angle are not allowed. A public recovery/reset is the sole normal prescribed exception for restoring its own known layout/poses; log it as `recoveryReset` and advance all restored logical generations even when a native body is reused.

The static checks establish only finite/non-interpenetrating initial conservative item AABBs and declared boxes, preserved IDs and a few necessary clearance conditions. They do not check the complete built scene, joints, support stability, actual sweep contact, steering accessibility or successful passage. Target body origins in the JSON are descriptions for public-input steering, never commands to write those origins. A physically unattainable target is a retained NOT_REPRODUCED/failed attempt and a design issue for review, not permission to teleport or weaken an assertion.

### Supplemental candidate geometry

The candidate receiver sensor slab is centered at (1.65, 0.5, 0) with full size (1, 0.04, 0.85) m. Its 0.04 m thickness is a newly declared M0 design value, not an existing measured property. It only nominates candidates. Full passage requires the actual maximum world Y over every child-shape support point to cross to or below the original plane y=0.5 from genuine inside-chamber provenance, through the chute. A Node/COM crossing, side entry, trigger enter or uncertainty near the plane cannot create a delivery.

The channel clearance volume is x=[1.15, 2.15], y=[0.5, 1.5], z=[-0.425, 0.425], with 0.04 m candidate wall thickness. Clearance counts every live inventory item, including non-snapshot items, not the door/structural walls/static fixture solids; those structures still require independent collision/sweep safety validation. The observation/CCD design speed bound is 12 m/s. This new bound is neither a clamp nor a measured capability; an exceedance is retained as out-of-contract failure without suppressing observations or awarding success. T34 must validate this observer and every compound crossing at the supported bound, including cases where an item crosses between endpoints. It must not rely only on a thin trigger's enter callback.

All these numbers supplement the new reconstruction; none are claimed to have been found in the lost version. Dynamic feasibility and the final implementation of the detector remain open T34 work.

## Event probes, deadline alignment and truthful outcomes

LIFE-A03/A12's transport probe is a **separate diagnostic fault-delivery facility**, not a public business command and not a normal-input path. It may capture a real immutable observation, retain its original tick/generations/body reference/hash, and deliver one unchanged extra copy after the original was handled. It may not create a crossing, alter identity/timestamps, suppress a normal event, seed a receipt/snapshot, set a score or claim that its copy is a new positive physical observation. The ordinary positive ledger must remain independently supported by original physics. Retain probe injection time separately from original observation time.

The old-generation cases must obtain their stale observations from an actual recovery or scene lifecycle, including real native body reuse for that designated case. Merely inventing a stale item ID in a JSON fixture is not BIZ08 evidence. The nuisance-item case is also physical: the actual door is intended to dislodge a real existing spare from its declared peg. If that does not occur during SHIPPING, the current-attempt non-snapshot case has not been tested.

LIFE-A13 does not set the clock or schedule a fake delivery at the cutoff. T34 may use one separately retained same-build calibration round to measure public submission-to-commit latency, then run at most three candidate neutral-wait offsets (-1, 0, +1 relative to that latency) per boundary. Each trial is a complete identified run with its own terminal. If no real coincidence is obtained, the boundary case remains NOT_REPRODUCED, with raw evidence; a specification revision or additional scoped investigation is required, not a widened timing window. Calibration success is not a prerequisite to freeze this M0 design.

### Bounded waits and failures

Navigation has a default 1800-active-tick cap and settling a 180-tick cap, bounded further by the running round's remaining budget. Shipping always keeps its 300-tick contract. Recovery and teardown have independent 5000 ms harness deadlines because simulation is paused during those operations; these wall limits are test-runner failure bounds, not extra gameplay time. The per-trial wall cap is 900000 ms. Each JSON row has explicit active-tick and terminal bounds; multi-round/variant limits apply per separately identified trial, never extend a gameplay round past its own budget.

A target that cannot be reached, a missing candidate/contact, an absent early crossing, a failed lifecycle allocation policy or a deadline miss is a retained failure/NOT_REPRODUCED, not a successful negative assertion. A cleanup teardown after that failure does not make the business case pass. Setup ticks, menus, duplicate diagnostic observations and repeated assertions never count as completed lifecycle rounds.

Required terminal evidence is a declared complete retry/round, genuine timeout, or explicit scene teardown. Record before/after world, body, shape, joint, target handle, pair, weigh receipt, native bytes and logical generations against the same declared baseline. A legal retained empty world is documented rather than assumed to be zero. Resource release and gameplay result are distinct assertions. The original five normal rounds plus fifteen anomaly identities remain required, and this work does not replace I05's hundred cycles or BIZ07's real desktop/Android/iOS and first-time human testers.
