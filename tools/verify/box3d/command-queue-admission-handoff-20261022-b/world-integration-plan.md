# Read-only World integration proposal

Status: **PROPOSAL, NOT IMPLEMENTED OR QUALIFIED**, 2026-10-22. No edits to the referenced engine/AIR/native files accompany this plan. The current n4 native source and its reported host results do not qualify a current WASM integration; m2 cannot substitute for the current facade. Frozen unified command decisions, wire and mutation-fence v1 remain unchanged.

## 1. Small ordered implementation checkpoints

### A. Real owner identities and transaction leases first

Proposed first ownership scope is seven AIR files: new `world-command-owner.ts`, plus `world.ts`, `shared-body.ts`, `registration.ts`, `rigid-body.ts`, `box-sphere-shape.ts`, and `world-writeback.ts`. Paths are relative to `src/air/physics/box3d/`. This is a requested future edit scope, not this checkpoint's authorization.

- World constructs one private owner/queue using the actual preparation generation; no global world lookup, second accumulator, RAF, public token or `impl` capability. Registration already has a closure-owned actual world (`registration.ts:34` onward); retain it.
- Maintain logical command identity separately from native allocation identity and component lifetime. SharedBody supplies an owner-only resolver closure for the mapper, not a public native-token getter. Only adopt successful allocations; ambiguous creation failures remain owned by terminal World cleanup.
- Track actual RigidBody/Collider component objects, each Node and raw ancestry, referenced shared/default material assets and the actual PhysicsSystem object. Existing `SharedBody.#references` contains adapter objects (`shared-body.ts:310`), so it cannot alone fence `Component.enabled/destroy`. Do not call the side-effecting `Collider.material` getter to discover asset identity.
- Add separate owner phases/admission: committed reads, command admission, configuration/lifecycle, collection, pure validation, commit, writeback, dispatch, faulted cleanup. Current `World.assertReady` (`world.ts:153`) and SharedBody `state/control` conflate read and mutation. A callback must still read last committed velocity/state; configuration and recursive step must reject.
- Install actual mutation leases over copied private identities and `Node.prototype`, plus a union transform lease over every body and ancestor, before invoking any callback. Preserve independent owners for shared material/ancestor objects. Always release temporary leases in `finally`; do not release persistent target guards there.
- Introduce no successful staged-force public path before a real consumer exists. A first source-only owner checkpoint may construct/mirror queue identity and exercise actual leases without changing ordinary force behavior or advertising hooks/targets. Once a staged path is enabled internally, missing native command capability must reject, not silently discard commands.

Acceptance for A is actual engine entry-point tests against real World ownership: changed flags/cache/listener/constructor/deferred-destroy effects must remain zero on rejection, shared owners remain independent, faulted close releases JS guards and still destroys the unique native world. Pure queue tests cannot establish that result.

### B. Admission owner and command wiring

Use `queue.withSubmissionAdmission` before any possibly rejecting owner resolution or original argument access. Its reader first acquires/reuses trusted owner fences from already-held identities, then validates logical component/world/generation/type and returns the original candidate for copying. Keep the leases until the outer call returns or throws. Acquiring a lease only during `step`, or releasing it when the reader returns, leaves ordinary ready-phase getters unfenced. An external `noteRejectedSubmission` notification is neither needed nor exposed.

The lead has separately agreed to freeze ready-admission's short-lived `Node.prototype` category restriction; do not silently broaden v1's stage list. This includes unrelated/orphan/UI/2D `Node.addComponent` calls during that narrow input-read window, with original behavior restored outside it. It is not a sandbox for arbitrary constructors, overrides, raw fields or aliases.

Actual RigidBody apply/clear entry points (`rigid-body.ts:141` onward) then route copied effects to this admission instead of `SharedBody.control`. Public velocity setters remain immediate outside transactions and explicitly forbidden inside; state/velocity getters remain committed-only. The independently owned `command-wire.ts` may translate a validated candidate and private logical-to-capability resolver, but does not authorize a candidate or prove lifecycle. World retains queue ticket identity and calls it only in its own candidate phase.

Do not export public helpers or activate feature registration in this step. Real current-schema WASM is required before any actual native success claim.

### C. One fixed tick and one native batch

`PhysicsSystem.postUpdate` is the sole automatic accumulator (`physics-system.ts:381`); manual `PhysicsSystem.step` must enter the same World path without adding time accumulation. Current World step is `world.ts:379`, with whole-body preflight before entering stepping.

1. Validate dt/substeps, safe queue/attempt/native-step/writeback counters and all bodies, including unrelated mass-pending bodies. Raw local/ancestor signatures precede world-cache getters. No producer runs in scene-sync-only calls.
2. Freeze owner/body roster; acquire temporary union leases. Snapshot the mixed producer roster/descriptor lease (`command-producers.ts:231`). Collect one candidate. A callback refusal drops all provisional commands, preserves prequeue/native snapshots and does not replay callbacks. Release the roster lease on every path.
3. Repeat owner/raw-local/full-world preflight after callbacks; use the actual facade pure whole-stream validation. A pure validation throw is not evidence of native mutation. `rejectCandidate` retains prequeue. Arbitrary user alias side effects are not rolled back or adopted as a new baseline.
4. Begin queue commit once, call actual `applyCommandBatch` once. Reviewed `not-mutated` keeps accepted prequeue; known `committed` retires it before any readback/step; `unknown` quarantines and faults. Never infer phase from a generic error code. Empty native apply does not invalidate snapshots, although the logical empty candidate can proceed to its tick.
5. After known commit, invoke actual `binding.step` exactly once. Record native completion separately from command commit. Capture all immutable native origin copies, perform the existing parent-first whole-batch writeback, then commit successful tick/epoch. Any later failure faults without replay. A completed native step remains counted even if snapshot/debug/Node copying fails.
6. Actual event dispatch must get its own transaction lease. Next-tick command submission may be admitted there as frozen public motion semantics require, but configuration/lifecycle/cancellation still reject. Current `World.emitEvents` is snapshot bookkeeping only (`world.ts:371`); it does not provide real collision-event qualification.

Native source references: `binding/facade.d.mts:62–72`, `binding/facade.mjs:1151–1155,1192–1229`. The current `world-binding.ts` world/component presence gates do not yet require the command APIs or establish current artifact qualification.

## 2. Persistent target guard and exact writeback composition

Keep each target's persistent transform lease active through admission, collection, native execution and synchronous Node callbacks. Never drop it temporarily to make writeback pass. The World privately records each lease's frozen covered-Node set.

Replace the writer's unconditional private lease (`world-writeback.ts:197`) with an optional owner-provided exact-write authority. For a Node, compose the transaction union lease and **all** persistent target leases covering it, including descendant-target leases that protect this ancestor. Nest `lease.write(node, operation, sameCopiedExpected, next)` for distinct leases and invoke the original setter exactly once at the innermost point. Do not grant a lease twice. If any owner is missing, the Node primitive must reject rather than bypass it.

`assertNodeTransformEntry` checks the whole registered owner set; `assertNodeTransformWrite` consumes all matching grants before events. Consequently a listener's reentrant setter cannot reuse any permit. No user callback runs in a guard-free transfer window. Expected local/world verification and the final whole-batch check remain in the current writer; readback never supplies a new expected baseline.

Temporary admission guards are gone before collection begins, or explicitly part of the same private composed set if a nested internal phase retains them. Target disposal keeps its lease until known paired-zero settlement. Faulted teardown releases it as part of owner cleanup without replaying unknown native commands. Independent foreign ownership remains a refusal; this does not grant permission to another World.

Before claiming complete counter behavior, specify a pure capacity check for the total exact-grant sequence budget or another reviewed, continuously guarded lease-renewal mechanism. Persistent lease grants can be consumed more than once per world tick, so existing world epoch checks alone do not prove that every grant counter is available before native commit. The present registry refuses exhausted grants before Node mutation; that does not roll back an already committed native batch.

## 3. Exact gaps requiring explicit decisions/early-entry work

1. **Pause notification:** `PhysicsSystem.enable` (`:107`) currently only guards and writes its cache. A false→true transition between ticks cannot be detected reliably by polling World at the next step. Add a narrow synchronous Box3D owner transition notification before promising immediate queue clearing/continuous disable. Distinguish `autoSimulation=false` manual mode from an actual pause; do not silently equate them.
2. **Recursive automatic stepping:** `postUpdate` increments `_accumulator` and resets `_subStepCount` before entering World. An owner-only World rejection is too late to preserve those caches if callback code directly reenters the actual System method. The earliest System guard is an additional minimal upstream edit to approve, separate from the existing setter guards.
3. **Component early reads:** RigidBody mass coercion/equality and other cached setters, Collider center/isTrigger, Box size and Sphere radius still have work before adapter calls. Box3D native-first cache ordering is not a universal pre-read fence. Audit exact public entry points in four upstream component files; attach opt-in assertions before any input read/coercion if this fence contract requires their refusal. Other backends remain no-lease paths.
4. **Inactive adapter paths:** `box-sphere-shape.ts:130` can copy/cache material on an inactive shape without a World readiness assertion; center/dimension inputs are copied before later candidate checks. Add explicit configuration admission at adapter entry, not just around eventual native calls. Do not count a cached inactive update as a native operation.
5. **Lifecycle mismatch:** RigidBody disable may leave native body enabled because colliders remain (`shared-body.ts:418`); detach can convert it to static (`:427`). SharedBody allocation can outlive the component. Therefore `releaseBodyAfterTeardown` cannot be called merely on component disable or type change to erase a protected zero. Define real settlement and component-generation invalidation, retain still-valid cancellation ownership, and retire continuous handles only after the actual state transition succeeds.
6. **Complete target lifetime:** target creation needs exact enabled-kinematic ownership, persistent Node/ancestor protection, type/disable/destroy revocation and protected paired-zero settlement. These are owner obligations, not consequences of queue `acquireTarget/revokeTarget`. No target/teleport API is implemented by this plan.
7. **Materials/config scope:** track both a shared asset and the default material's actual identity, refresh ownership after a successful outside-transaction material replacement, and include disabled colliders. `EVENT_UPDATE` occurs after direct asset mutation; guards must be installed before public material setters. Raw asset/internal alias writes remain non-sandbox side effects.
8. **Scene scope and mirrors:** current origin writeback rejects unsupported mirrored ancestor/static-child synchronization scenarios. This plan does not close those C11 gaps or runtime parent/scale edits. Union leases must protect all affected ancestors; guarding only current body Nodes misses ancestor writes and orphan component creation.
9. **Physical qualification:** require a new strict current-source/current-WASM fixture identity, actual original PhysicsSystem/manual and automatic entry paths, real batch/step counts, copied committed-state reads, real debug/counters, known/unknown injected delivery failures clearly labeled, and complete app close/resource-zero. Preserve earlier immediate-force fixtures as historical rather than falsely claiming their old semantics remain current.

The next requested implementation window should select checkpoint A explicitly, settle the System/pause and grant-budget seams, and preserve its source checkpoint before expanding to B/C. No public activation, formal 2128-gate change, or complete T11 claim follows from any pure module control result.
