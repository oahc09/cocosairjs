# Upstream candidate verification

This is the execution guide for [the upstream update plan](../../ai/plans/upstream-update.md), not a PASS certificate. The [ledger](../../ai/ledgers/upstream-update.md) separates implementation, current CPU results, retained failures and infrastructure limitations. No merge, release, deployment or remote workflow dispatch is part of this change.

## Candidate order and identity

1. Finish source, examples, dependency installation, metadata, tooling and formatting. Preserve failed attempts.
2. Run `npx tsc -p tools/verify/upstream-update.tsconfig.json`, focused Node/Jest contracts, and existing static checks. This config preserves the root ambient types and strictness, while adding the example/readiness/skinning-fixture source and ES2022 library declarations, with an ES module/ES2017 target for browser top-level await. It does not enable `skipLibCheck`.
3. Build main/min/declarations/package once with `npm run build:all`, then the separate `npm run build:spark`. The two runtime builds consume two different build numbers. Do not rewrite counters to pretend the artifacts are identical.
4. Run the actual installed consumer, including the explicitly supplied pinned modern TypeScript. Complete `node tools/verify/upstream-run-cpu.cjs --out=<new-directory>` if the full smoke inventory is required. This runs every on-disk smoke suite in isolated batches of eight, preserves each raw Jest JSON/log, rejects skipped/missing/changed suites, and never changes the canonical inventory. A subset or failed batch is not a full PASS.
5. Freeze using `node tools/verify/upstream-gates.cjs --freeze=<new-snapshot.json>`. It hashes the on-disk source/tool/test/example/document/Skill inputs and required main/math/Spark artifacts. This is an identity snapshot, not execution evidence and not proof that an intentionally partial source checkout contains historical files. Full Gallery/deployment evidence uses the existing campaign's stronger input inventory and staging rules.
6. Collect applicable actual browser/device evidence and full live Gallery coverage against that frozen candidate. Rebuild/recollect related results after any input changes. Do not change a fingerprint to make historical results current.

The new Gallery count is 196 (188 preserved entries plus eight drafts), not a fixed historical 182. All 196 static specifications are frozen and pass validation; the eight new examples retain draft runtime status and no promotion. Seven original source-line anchors were corrected against unchanged main source after preserving their baseline drift evidence. The original manifest's unrelated status/promotion differences are retained rather than normalized. Static source bindings do not count as API effect evidence.

## Declaration compatibility is a separate gate

Runtime value-export parity does not establish TypeScript compatibility. Compare the exact main declaration blob, a same-environment fixed-main control, and the candidate with the same legal type/`typeof`/member-access probes under all four supported compiler modes. Preserve public return-type inference and negative tests that reject accidental `any`. Separate genuine public type regressions from pre-existing environment-generated private names and unsupported package subpaths.

The declaration generator derives default runtime value names from the shared default feature list, while retaining the original current-source all-feature type graph. Existing optional Spark root names and generated namespace dependencies remain available as types only; this never adds Spark runtime values to the default engine or creates a new package export. The separate Spark declarations and package export map keep their existing boundaries. Alias inventory errors such as namespace-local `export { find }` are corrected in the inventory tool, not by changing the API. Failed candidate packages and baseline-PASS/candidate-FAIL/fixed-candidate results must all be retained independently.

## Engine and Agent gates

`node tools/verify/upstream-gates.cjs --snapshot=<snapshot.json> --engine=<engine.json> --agent=<agent.json> --out=<new-gate.json>` checks track separation, exact snapshot hashes, the complete frozen 36-case/dimension inventory, evidence existence/hashes, duplicate/subset/skip cases, and positive versus expected-negative results. Evidence-backed inapplicability may complete an individual research decision but never becomes positive feature support. Unfinished experimental work still blocks full plan completion.

The Agent protocol is [agent-protocol.json](../../tools/benchmark/upstream/agent-protocol.json). It prepares twelve task prompts, three repeats and two arms: 36 pairs / 72 runs per configuration. Control and candidate configurations require 144 runs combined. Existing `isEligible`/`aggregate` from `tools/benchmark/runner/metrics.ts` are reused; repair budget 5 and time budget 20 minutes are preserved. Model/provider revision, actual generation inputs/outputs, seeds/parameters, frozen package/knowledge identities, token/time/cost observations, public API misuse and validation coverage are required. Infrastructure exclusions and policy denials stay visible; fewer than 36 available matched pairs blocks this cohort.

The current protocol remains BLOCKED. Exact public resources, old/current knowledge corpora and the existing three@0.186.1 artifact are prepared independently of generation. Control and candidate Cocos archives have real bytes and separate provenance; the main control is a same-environment rebuild from verified main source, not the original historical binary. Protected references and common observation validators are source preparation, not browser-validated matched arms. The real immutable provider/model route, paired browser observations and host isolation remain unresolved. A subsequent upstream-sdk-types/3 preparation correction freezes @types/three@0.186.0 and its complete dependency lock. Common AU12 comparison uses the unchanged TS5.9.3 node16/bundler modes, while Cocos still requires both legacy TS4.9.5 modes. The earlier declaration-identity blocker was incomplete preparation, not an unavailable external service or a required user decision. See [the correction record](../evidence/upstream-update/THREE-DECLARATIONS-REVISION.md). A001 copies protected reference solutions; neither it nor native assistant-generated examples can be reported as real Agent runs. Unit fixtures for the gate are explicitly synthetic. No credentials, model routes or external generation services were configured.

## Paired preparation and fail-closed receipts

`tools/benchmark/upstream/prepare-inputs.cjs` validates the public bank and curated knowledge without invoking a model. Use a new `--out` and explicit `--execute` only to materialize a new public bank; never expose protected reference sources to the generating process. Old/current knowledge changes form separate comparison configurations. The three version is inherited from the existing preparation and is not upgraded. The U06/AU12 caller type contract explicitly preserves `skipLibCheck: true` with strict null checking and both positive and negative consumer cases; it does not impose whole-library strict declaration checking.

`tools/benchmark/upstream/reference-contracts.cjs --three-package=<exact-extracted-package>` checks protected source identities and reports precise missing semantics, package decisions and execution evidence separately. `references/collect-reference.cjs` requires the explicit `--execute-protected-reference` flag plus `--engine`, `--task`, `--seed`, `--out`, `--engine-artifact`, `--runtime-file` and `--three-package`. This is a protected reference collector, not a model benchmark or permission to change routing. Each reference is captured before generated trials, with the same task inputs and frozen seed. Its actual runtime module must equal the corresponding public export bytes in the verified archive.

Agent admission additionally takes trusted `--cocos-artifact`, `--three-artifact` and `--three-package` paths. It reopens all retained reference receipts, verifies their archive/runtime/source/input identities, and recomputes their common observation assertions for every task, engine and repeated seed. Receipt artifact paths are relative to the containing receipt directory. A `referencesBrowserValidated` boolean, matching arbitrary hashes, or validator name alone cannot admit a cohort. A generated PASS also requires raw observations that pass the independently frozen task contract. Synthetic unit fixtures and boundary mocks test rejection logic only; they are never reference or generated outcomes. With no observed model trials, measured performance metrics are null rather than an invented zero-percent score.

## CI and limits

`Code quality / quality` keeps its original event routes, classifier, mandatory core tests, five real Chromium examples and failure retention. Focused upstream CPU contracts and one bounded native state/target collector are added. Unknown/shared paths still select all retained suites. The Box2D matrix remains unchanged. Full Gallery, all browsers and research experiments are not forced into every PR.

In the current cloud environment, browser launch is INFRA_BLOCKED; this is not evidence that WebGL2 is unsupported. Real Firefox/WebKit, compositor scenarios, Android/two GPU families, full Gallery and Agent generation remain missing. A green ordinary PR would not clear those gates. `npm run verify:release` remains independently authoritative and must fail on missing, stale or uncommitted evidence.

The exact frozen-scenario bindings are recorded in [execution-map.json](../../ai/ledgers/upstream-update/execution-map.json), without changing the M0 thresholds or dimensions. [Material transition pairs](upstream-material-transitions.md) add strict native mutation-versus-rebuild, R/G texture semantics and transmission disable/re-enable/destroy/recreate pixel/binding comparisons. [HTTP request matrix](upstream-request-browser-matrix.md) adds the dedicated native U01 browser cases. Both are prepared and NOT_RUN, not substitutes for actual browser evidence.

The dedicated U08 collector is `node tools/verify/upstream-experiment-browser.cjs --browser=chromium --out=<new-directory>`. It retains all ten configurations and never labels JavaScript SH projection as GPU convolution. U01, U05 and U08 have an offline `--record-not-run=<verified blocker>` option which does not listen or launch; its nonzero result is a limitation record, not an attempted execution. Run other browsers separately without changing their frozen dimensions. Native installed-SDK browser collection accepts `--browser=chromium|firefox|webkit` on `tarball-browser-consumer.cjs`, with explicit pinned `--vite=<installed package>` when running Vite modes.

The shared state/readiness/showroom and installed-SDK collectors now own their Playwright child and require its physical `close` event within bounded shutdown, not only a disconnected browser transport. Missing app release/close receipts fail the corresponding scoped collection. This does not replace the full Gallery campaign's stronger descendant-reaping protocol. All these changes are collection preparation, not evidence that a browser ran.
