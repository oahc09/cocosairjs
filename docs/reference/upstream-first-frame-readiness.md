# First-frame observation, not a universal ready API

`tools/debug/readiness-observer.ts` is verification tooling, not part of the runtime entry. It keeps engine creation, declared resource completion, actual scene-pass availability, frame submission and browser compositor presentation distinct. It never calls `tick(0)`, runs warmup frames, compiles a shader, starts resource work or changes `inspectAir*` behavior. Callers supply the observations and own their resources.

A single deadline or abort produces a terminal report with the last stage and retained diagnostics; observer cleanup runs on every exit. Missing GPU/compiler observation is `BLOCKED`, not a guessed PASS. Failure, context loss, invalid submission, blank/mismatched compositor proof and business-state mutation are explicit failures. The before/after snapshot covers application-chosen animation time, physics step, random sequence, timers, input and business-event counts. It must contain finite JSON values. It is not a claim that arbitrary native callbacks are side-effect free.

The native fixture at `test/fixtures/upstream-readiness/` preserves the context attributes requested by `createAirApp`. It records actual draw calls/program link status, the first AFTER_DRAW after its fixed local resource and scene exist, and GPU readback. It does not access the lazy `WebGL2Shader.gpuShader` getter from an inspector, because that getter can compile. The external collector independently captures and validates compositor PNGs before supplying a matching submission receipt. The ordinary static fixture has no business clock to warm up; future application fixtures must supply their own complete state digest.

`node tools/verify/upstream-readiness.cjs --browser=chromium --out=<new directory>` prepares five cases: cold, delayed declared resource, an additional offscreen pass, deliberate native EffectAsset/Material shader-compilation failure and actual context-loss injection. The shader-failure case observes final native shader compilation, but does not claim coverage of every Effect failure path. Unsupported context-loss injection is BLOCKED. Expected failure recognition never implies positive rendering support. Reports preserve source/SDK hashes, actual browser/renderer, logs, PNGs and bounded owned-child close event plus browser transport/context closure acknowledgments. Existing output is rejected, not overwritten.

CPU protocol tests pass separately from browser evidence. All five real-browser cases are currently **INFRA_BLOCKED / NOT_RUN** in this cloud execution path. There is no compositor, cold-start timing, Firefox/WebKit or mobile claim. Native Effect fault execution and full application state coverage remain requirements for broader acceptance.

The shader-failure case now constructs a deliberately invalid native EffectAsset and Material. A read-only compile observation records its final WebGL2 shader source and native compilation failure; the observer does not compile programs or force lazy getters. A direct raw WebGL compile control is no longer substituted for this native path. The collector accepts explicit --browser=chromium|firefox|webkit, with no backend fallback. This upgraded fixture remains NOT_RUN in a real browser.
