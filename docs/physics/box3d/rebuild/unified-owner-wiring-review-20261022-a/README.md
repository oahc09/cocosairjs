## Conclusion

The next useful implementation is an actual dynamic-body producer/ordinary-command path through the existing AIR owner and `PhysicsSystem.step/postUpdate -> Box3DPhysicsWorld.step`. Reuse `Box3DCommandQueue`, `Box3DCommandProducers`, `mapCommandCandidate`, and the current N4 `validateCommandBatch/applyCommandBatch`; do not create another protocol, standalone fake owner, or new native build. Complete source-level admission and failure handling before enabling the path.

Both existing N4 Debug and Release artifact sets were hash-checked without loading/executing them: 50 current build inputs per set, zero input drift, all manifest artifact hashes and lengths match, and packaged facades equal current source. See `n4-readonly-identity.json`. This is identity evidence only, not new physics PASS evidence.

Public unified activation remains blocked by the frozen material all-owner prerequisite and incomplete target/scene/lifecycle seams described below. A real, limited dynamic producer test is useful and must be labelled limited; it cannot remove those blockers or narrow the denominator.

## Required owner seams and invariants

### A. Authentic submission and caller-input fencing

- Resolve actual public RigidBody -> initialized component record -> same live logical body -> private native capability, under the current PhysicsSystem/world/preparation generation. Do not accept impl metadata, raw IDs, cloned tokens, `Object.freeze`, or map structure as ownership proof. Check pending destruction/lifetime as well as existence in the Map.
- Dynamic effects and continuous ownership require the **component** to be enabled and the actual native state to be enabled dynamic. `enableRigidBody(false)` can leave a native body enabled while colliders remain (`shared-body.ts:449-456`); a native-enabled bit alone is insufficient.
- Put original component resolution, owner admission, and every original vector/offset/pose/options field read inside `queue.withSubmissionAdmission`. Establish/reuse the owner fence from that reader and keep it through the entire queue call, including its copy/publication. Do not evaluate `this.body`, `bodyVector`, or public getters first and then call `queue.submit`: a caught rejection would escape the collection failure latch. Do not invalidate snapshots or mutate native state when enqueueing.
- Retain immediate velocity getters as committed native reads. Leave velocity setters outside the command union; reject them during collection/validation/commit. Keep all other configuration and lifecycle mutations fenced. A caught non-command configuration refusal does not by itself have to abort collection; a caught rejected **command submission** does.
- Existing `ProducerOwner.assertConfiguration` only checks a moment in time. `registerContinuous`, `update`, and enabled-options reads occur later under the producer's local `#reading` flag, not an owner-wide fence. An input getter could mutate native/Node/material configuration without reentering the producer registry. Add an owner-scoped full-operation admission/copy lease or equivalent private wrapping of every handle operation. An assertion alone is not that lease.
- Public Cocos velocity setters (`components/rigid-body.ts:632-657`) guard only `this`; the generic guard checks exact identities, and the owner registers only owned components. An unowned/uninitialized body setter therefore is not rejected by the current transaction fence. Add a narrow backend-neutral early-entry gate for these public entries, active only during the Box3D transaction. Merely registering `RigidBody.prototype` is ineffective unless those entries explicitly check that identity. Preserve other backends and record extracted-source differences in the required upstream map/docs.

### B. Real roster and pause/lifecycle participation

- Snapshot exactly one roster for each candidate logical tick. All pre-tick accepted entries precede roster contributions. Preserve stable mixed hook/continuous order and force-before-torque at each continuous position. Do not rerun callbacks on failure or invoke a lease twice.
- Avoid the phase deadlock: `producers.snapshot()` calls owner configuration admission, while `beginStep()` puts the owner in preflight. Snapshot while still ready and immediately open the transaction fence, or add a narrow private snapshot admission within preflight. Do not broadly permit public configuration in preflight. Retain and independently dispose both roster and owner leases in finally.
- The same conflict exists for pause: `installSystemControlObservation.open` already enters `control` before participant preflight, but `producers.preparePauseTransition` calls public-style owner configuration admission. Give its internal participant path private control-context admission. Prepare queue **and producer** transitions before System cache writes, then commit both; if either entered effect fails, fault and retain truthful partial-state diagnostics, not rollback.
- Update bootstrap-disabled handling too. Pause clears user queue/pending motion, disables continuous entries, and preserves hook enabled flags. Resume does not re-enable continuous entries. Cleanup disable/dispose remains allowed paused, not during an active transaction.
- Wire successful RigidBody disable, non-dynamic type change, detach, body destruction, scene cleanup, and world close to continuous retirement and queue/target obligations. Do not infer native disable from a disabled component with live colliders. Distinguish actual successful native teardown from cleanup in an already faulted world.
- Current records have preparation generation and Node ancestry, but no explicit producer scene-generation/persist ownership policy. Hook registrations are bodyless. Scene transitions must remove only their owned hooks/handles/entries and preserve genuine persist ownership; app/world `close()` alone does not prove scene lifetime correctness.

### C. Whole-world readiness and native phase truth

- Under one fence and before any command write, preflight every owned world body, including unrelated pending-invalid dynamic bodies; check actual native step index unchanged and strictly below MAX_SAFE_INTEGER; reserve queue tick/attempt limits and the existing writeback epoch. Keep sequence exhaustion distinct from cancellation/cleanup. `world.ts` currently checks writeback epoch but not `nativeStepIndex < MAX_SAFE_INTEGER` before a future command commit; the facade checks native step exhaustion only later inside `step`.
- Authenticate the exact queue candidate and build the private logical-body/token Map from its owner records. Recheck generation, component type/enabled status, and body ownership before mapping/commit. Cancellation must use identity/lifetime admission only, without preflight of pose, mass, or command arithmetic, so invalid queues remain recoverable.
- Use `mapCommandCandidate` unchanged for supported operations. It converts `impulse` -> `linearImpulse`, `angular-impulse` -> `angularImpulse`, teleport -> reset, and idle/protected null sequence -> flagged native zero sequence. Do not reconstruct tokens, sort operations, combine impulses, or retain the accepted log only in its reduced form.
- Pure validation is optional extra planning but never a reserved plan/capability. If used, call the existing `validateCommandBatch` once after mapping, then `applyCommandBatch` once after final readiness. The apply entry itself replans. Never replay one immediate native setter per command.
- Distinguish `not-mutated`, `committed`, and `unknown` using the facade's immutable own `mutationOutcome` descriptor and known local call phase, not an error code, nativeStatus alone, truthiness, or a guessed nonzero status. Read-only validate throws preserve native observations. Nonempty apply throws without known preflight proof are unknown and quarantine/fault; status-zero/readback errors are committed and retire/fault without stepping.
- Empty successful apply is native **not-mutated**, but the logical tick still needs to advance through an accepted candidate to one solver step. The current queue exposes only `finishCommit('committed')` for its awaiting-step transition. Make that logical-consumption/native-mutation distinction explicit in the coordinator/diagnostics (or add an explicit empty-success transition); do not pass 'not-mutated' and then call completeTick from the wrong phase, and do not advertise a nonempty native commit.
- After a successful commit call exactly one solver step. Complete the queue tick only from actual solver completion diagnostics. On later snapshot/Node failure, `faultAfterCommit(candidate, actualNativeCompleted)` preserves completed native ticks and prohibits replay. Do not advance a tick merely to conceal command-readback failure.
- Always unwind queue ticket, roster, and owner scope independently; preserve falsy first failures. The current queue.close excludes collecting/validating/committing/awaiting-step, so every coordinator exit must explicitly settle/reject/fault its candidate before terminal cleanup. Do not rely on owner.fault() alone: it currently changes owner phase, not queue phase.

### D. Actual-state publication, not prediction

- Keep an internal copied command receipt containing accepted-original/reduced-operation identity, command outcome, actual immediate native body/operation values, and separate solver/writeback outcomes. The facade receipt contains opaque native body capabilities: do **not** return it raw in public World diagnostics or helper handles. Publish sanitized copied observational identity/values only.
- `Box3DSharedBody.state` already reads committed native state and has no speculative velocity cache. No enqueue-time velocity publication is needed. Preserve last committed reads in callbacks; neither target requests nor planner shadow values become component/native truth.
- Nonempty command commit invalidates current observations independently of the later solver. Keep old copied snapshots unchanged; distinguish historical copied snapshot, current native snapshot availability, and pending event publication. Do not invalidate merely for pure refusal/empty apply.
- After solver completion capture actual native poses for **all** shared bodies, not just packet bodies; wakes and solver effects can include peers. Continue using `captureWriteback -> writebackSceneBatch` with exact-operation/expected-pose grants, all-owner checks, and all baseline commits only after verification. Store native command receipt, completed solver snapshot, and successful scene-cache publication as distinct facts. Current `world.ts:607` stores its snapshot before Node writeback; adding a command receipt must not make that field imply successful Node publication.

## Explicit remaining activation blockers

- **Shared-material completeness:** frozen `shared-material-values-decisions-v1.md:14` explicitly blocks full all-owner qualification and unified consumer activation until actual mixed-backend binding completeness has a neutral binding ledger. Current private material work may close its scoped lifecycle, but this review does not convert that into all-owner proof or erase the freeze. Coordinate the integrator's prerequisite decision before public activation.
- **Targets and teleports:** no actual public target ownership/handle installation exists. The primitive `node-motion-guard.ts` is not integrated. Every overlapping persistent and temporary transform owner requires its own exact grant (`node-transform-validation.ts:155-214`), while World scope currently grants only its temporary lease. A persistent target guard cannot simply be added alongside it. Reserve sufficient grant budget for the full planned writeback before native mutation; the primitive exposes no such budget reservation today. Never dispose persistent protection temporarily to bypass this.
- **Disabled teleport publication:** N4 permits disabled dynamic/kinematic reset. Current `captureWriteback` marks disabled bodies unwritable, while final `writebackSceneBatch` still compares every Node to the actual native pose. A disabled reset with changed pose would therefore leave Node old and fail after commit. Give a verified reset-affected disabled body an explicit actual-pose publication path, without enabling/waking it. This does not block a dynamic-force-only experiment, but it blocks full teleport support.
- **Scene synchronization:** `Box3DSceneTransform.preflight` rejects external pose/parent/scale changes; syncSceneToPhysics only preflights. Queue CommandInput/wire mapper has no internal scene-reset producer path. Do not call arbitrary Node edits supported or inject scene resets as user teleports. Frozen motion/scene/lifetime requirements need separate actual integration.
- **Early entries and scene/persist ownership:** complete the unowned velocity gate, source-wide transaction admission, genuine scene-bound producer cleanup, and protected-zero settlement. Target cancellation is not native cleanup; no zero may be sent to a reused body.
- **Evidence:** queue/producers/wire controls are CPU logic tests, not proof of AIR/native consumption. Existing N4 hash identity is not a new runtime result. Current dynamic component tests assuming immediate impulse readback need an explicit migration/new expectation with historical failures preserved, not a claimed core regression or deleted scope.
