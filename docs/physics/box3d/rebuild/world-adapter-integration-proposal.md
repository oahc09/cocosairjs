## Exact engine lifecycle

### Selection is not construction

1. `requestAirApp` normalizes/adopts options and publishes the one initialization Promise before the initializer executes. Equivalent concurrent calls share that Promise; failed initialization requires reload. See [app-config.ts:368–409](../../../../src/air/app-config.ts#L368-L409), and admission at lines 330–359.
2. `initializeAirApp` creates the ownership transaction before its first await. Selected Box2D3 preparation completes first; selected Box3D preparation completes second; only then is `game.init` entered. The PRE listener is registered after feature modules have registered their listeners. See [bootstrap.ts:123–162](../../../../src/air/bootstrap.ts#L123-L162).
3. `prepareBox3D` awaits the real ST lease and owns `box3d:module` before awaiting the adapter factory. The factory must prepare a synchronous selector closure, not a second world/simulation loop. See [prepare.ts:84–92](../../../../src/air/physics/box3d/prepare.ts#L84-L92).
4. `game.init` emits `Game.EVENT_PRE_SUBSYSTEM_INIT` at [game.ts:822](../../../../src/cocos/game/game.ts#L822), before `director.init()` at line 855. The AIR listener calls `threeD.select()`, then `selectPhysicsBackend('box3d')`, then the independent 2D lease's selection. `threeD.select()` must only synchronously register the lease-bound constructor/wrapper. `selectPhysicsBackend` re-registers the requested wrapper last and seeds the existing default material; it rejects any already-created world. See [physics-backend.ts:64–98](../../../../src/air/physics-backend.ts#L64-L98).
5. `selector.register` sets the current wrapper while there is no world; it does not instantiate it. [physics-selector.ts:127–136](../../../../src/cocos/physics/framework/physics-selector.ts#L127-L136).
6. `Director.init` emits `DirectorEvent.INIT` at [director.ts:885](../../../../src/cocos/game/director.ts#L885). The physics module's once-listener invokes `PhysicsSystem.constructAndRegister`. `doConstructAndRegister` creates the singleton, calls `resetConfiguration`, then `constructDefaultWorld`, then registers the system. [physics-system.ts:875–912](../../../../src/cocos/physics/framework/physics-system.ts#L875-L912).
7. `constructDefaultWorld` calls `new selector.wrapper.PhysicsWorld()`, stores it, then calls `setGravity` and `setAllowSleep`. These are mandatory startup calls, not optional future component support. [physics-selector.ts:184–194,256–261](../../../../src/cocos/physics/framework/physics-selector.ts#L184-L194).
8. Default material installation occurs through the post-project initialization delegate, not the world constructor. `setDefaultPhysicsMaterial` calls the world's `setDefaultMaterial` and attaches the material update listener. [physics-system.ts:216–249,863–879](../../../../src/cocos/physics/framework/physics-system.ts#L216-L249).

Do not call `selector.switchTo` as a startup shortcut: it creates worlds and may destroy one. Its actual runtime gate is `runInEditor`, whose default is `!EDITOR`; the AIR backend file's editor-only explanatory comment must not be used as authority to permit hot switching. AIR explicitly rejects late selection. Preserve that restriction rather than modifying selector semantics.

### Proposed AIR-owned wiring

- Add a real `world.ts`, a small lease-bound registration factory, and explicit unavailable-component constructors under `src/air/physics/box3d/`. The optional feature registers the factory with `registerBox3DWorldAdapter`, without fetching or registering Box3D with the engine at module evaluation.
- The factory closes over the exact `lease`, normalized options and preparation generation. Its wrapper's parameterless constructor creates one `Box3DWorld`. It must reject a second construction, a closed/faulted preparation or a foreign owner. Avoid a mutable global “latest prepared module” that an independent diagnostic load could replace.
- `select()` checks that no engine world exists and the preparation is still valid, then registers the same wrapper under `box3d`. Repeating selection before construction may be idempotent; it must never recreate a world. The existing following `selectPhysicsBackend` call remains the final selection point.
- Create the native world synchronously in the constructor, using the already-ready binding. Register its actual acquisition immediately with `preparation.own('box3d', 'world', disposer, { dependsOn: ['module'] })`, before any additional fallible initialization. Do not register an unacquired world or rely on the constructor returning before ownership is recorded.
- Guard duplicate/closed construction before native allocation. If acquisition registration itself fails, distinguish an unregistered resource from a late acquisition already accepted for defensive self-release; never destroy both ways. No asynchronous operation belongs in this constructor.
- Keep runtime wrappers, `Node`, `PhysicsSystem` and selector imports in the single existing main runtime. An internal test entry can access the concrete adapter/foundation, but do not publish a second runtime or public raw-body escape hatch for examples.

`selector` currently substitutes no-op objects for missing world, rigid body, shapes, constraints and controllers. T09 must populate unsupported component slots with constructors that throw a specific capability error before native mutation. Registering only `PhysicsWorld` would let `RigidBody` silently become `ENTIRE_RIGID_BODY`. Cover every currently recognized slot in [physics-selector.ts:45–63](../../../../src/cocos/physics/framework/physics-selector.ts#L45-L63); replace these rejects with real implementations only in the relevant later task.

### Fixed tick and fault semantics

[PhysicsSystem.postUpdate:352–381](../../../../src/cocos/physics/framework/physics-system.ts#L352-L381) already owns the accumulator. Its per-tick order is `syncSceneToPhysics → step(fixedTimeStep) → emitEvents → syncAfterEvents`. `BEFORE_PHYSICS` and `AFTER_PHYSICS` are emitted once per 3D postUpdate frame, outside the fixed-step loop, including frames without a completed tick. They must not become the per-tick target/force hook. T11's formal before-step command hook belongs inside the world step after scene synchronization and before the one native call.

The adapter step should do: validate alive/idle and positive float32 dt; enter stepping phase; record attempted tick and solver subdivision count; call `binding.step(world, dt, solverSubSteps)` once; retain the immutable step snapshot; record completed native tick and optional debug/counter observations; leave stepping phase. T10/T11 will insert upload and body-origin writeback at the stated boundaries. No T09 fixture should invent Node synchronization to bypass that dependency.

The current facade already performs pre-step transform copy, one `_air_b3_world_step`, then post-step event/contact copies: [facade.mjs:374–395](../../../../src/air/physics/box3d/binding/facade.mjs#L374-L395). Do not duplicate its native step or recollect raw events later after mutations. The batched transform copy is one C call for the batch, but contact enumeration currently visits owned bodies separately; do not describe the entire snapshot as one boundary crossing.

Manual `PhysicsSystem.step` forwards its optional arguments but does not call scene sync/events/post-event sync, and does not check `enable` or `autoSimulation`: [physics-system.ts:442–464](../../../../src/cocos/physics/framework/physics-system.ts#L442-L464). Proposed Box3D contract: accept the one-dt form, explicitly reject defined legacy `timeSinceLastCalled`/`maxSubSteps` arguments before native mutation. This avoids silently ignoring an intended Cannon-style accumulator. Document this backend restriction; do not change Cannon behavior. Manual callers own the surrounding sync/event calls.

A snapshot-copy failure is not a failed native step. Current `AIR_E_BOX3D_SNAPSHOT_UNAVAILABLE` is thrown after native advancement and after incrementing the internal step index. The engine accumulator is only decremented after the whole callback sequence succeeds. Therefore a snapshot/debug/post-step failure must latch the adapter faulted and stop further automatic/manual native advancement until explicit teardown. Preserve `nativeCompleted=true`, tick/dt/substeps and `snapshotAvailable=false` in diagnostics; do not retry the same tick or parse prose to guess execution. Add a typed, read-only step diagnostic getter or structured error fields as a small facade extension. Successful debug collection must not alter the event/contact mutation revision.

Paused system behavior must stay exact: `enable=false` still calls scene sync but adds no elapsed time; `autoSimulation=false` performs no automatic work. Catch-up beyond `maxSubSteps` remains in the existing accumulator. No default cap/lag-drop change is part of Box3D.

### Debug implementation, not flag storage

Map `WIRE_FRAME=1`, `CONSTRAINT=2`, `AABB=4` from [physics-enum.ts:398–431](../../../../src/cocos/physics/framework/physics-enum.ts#L398-L431) to native `drawShapes`, `drawJoints` and `drawBounds`. Pass validated constraint size to `jointScale`; keep contact-point/normal/force drawing disabled in this foundation.

`b3World_Draw` ordinary shape drawing requires `b3WorldDef.createDebugShape`, `destroyDebugShape` and `userDebugShapeContext`. Without them the current world has no `userShape`, and the shape draw callback is skipped: [physics_world.c:1315–1359](../../../../vendor/box3d/core/src/physics_world.c#L1315-L1359). Install static C callbacks at world creation, copy supported sphere/hull geometry into bounded owned native debug records, and free that cache on shape change/destruction/world destruction. Never retain borrowed shape geometry pointers beyond their promised lifetime. Reject unsupported geometry/capacity instead of drawing nothing successfully.

Emit copied line/bounds/primitive records through static C callbacks described at [types.h:3060–3144](../../../../vendor/box3d/core/include/box3d/types.h#L3060-L3144). The bounds callback receives the native fat AABB, not an exact tight visual bound (`physics_world.c:1363–1365`); label and test that distinction. Test hull/sphere wire geometry against known fixture transforms, not only a nonzero line count.

Consume records with the existing engine camera `GeometryRenderer`, following the renderer access pattern at [cannon-world.ts:270–297](../../../../src/cocos/physics/cannon/cannon-world.ts#L270-L297), not a new canvas/RAF. No camera/renderer means an explicit diagnostic “collected, not presented”, not proof of visible drawing. Validate `CONSTRAINT` and scale using a small native test fixture with a real joint; that fixture need not expose a Cocos joint adapter. If this real proof is deferred, keep that bit explicitly unsupported and T09 debug coverage correspondingly incomplete.

### Material boundary to freeze before exposing success

Cocos defaults are friction 0.6, restitution 0, rollingFriction 0 and spinningFriction 0 (`physics-material.ts:137–146`). Native `b3SurfaceMaterial` has friction, restitution and rollingResistance, but not a directly named spinning-friction field; rolling resistance is documented for spheres/capsules only: [types.h:417–443](../../../../vendor/box3d/core/include/box3d/types.h#L417-L443). Do not silently rename every Cocos field into presumed equivalent native behavior. The smallest T09 material subset can implement verified friction/restitution and accept the existing zero rolling/spinning defaults, while explicitly rejecting nonzero unqualified fields before any inherited shape changes. Nonzero rolling behavior and full shared-material semantics need their own frozen mapping/tests, not a successful cached setter.

### Public setter rollback is an integration issue

`PhysicsSystem.gravity`, `allowSleep` and `setDefaultPhysicsMaterial` write their cached state before calling the adapter; `resetConfiguration` writes several fields before delegating. See [physics-system.ts:120–125,165–170,216–219,389–423](../../../../src/cocos/physics/framework/physics-system.ts#L120-L125). Merely throwing inside the adapter preserves native state but can leave public state changed. Do not claim public invalid-input rollback from a direct facade rejection test.

Proposed resolution for the live world setters is a narrowly reviewed engine change that validates/commits the backend operation before publishing the new `PhysicsSystem` backing value, with an atomic validated Box3D configuration path for `resetConfiguration`. Preserve old backend successful behavior and verify its ordering-sensitive tests. Any extracted-source change requires the usual upstream-file-map/UPSTREAM record; do not silently patch the engine or recursively call public setters to hide a failed commit. Material replacement/shared-material field mutation needs its own validate-all/rollback design before claiming that path complete; full shared-material propagation remains the later material work. T09 may implement and prove initial default installation plus the owned low-level shape subset, but must retain the unimplemented shared-material subcases explicitly.

## Ownership and failure boundaries

- The prepared module lease belongs to the admitted application transaction, not a scene. A native world depends on that lease. The facade owns its scratch allocation and all its issued world/body/shape capability tokens; callers must not reconstruct tokens from copied numeric IDs.
- World ownership must be captured even if the world constructor or subsequent `setGravity`/`setAllowSleep`/material initialization throws. `game.init` failure after Director initialization must release that real world, not just a prepared-but-unused module.
- `preparation.dispose` processes resources in reverse order, retains dependencies of failed releases and continues independent backends: [preparation.ts:95–107,160–177](../../../../src/air/physics/preparation.ts#L160-L177). A failing `box3d:world` therefore retains `box3d:module` while 2D cleanup still runs. Do not bypass it with an unconditional `lease.dispose` finally block.
- The raw facade's `destroyWorld` rejects a second call; wrapper `destroy()` must own idempotence. The facade `dispose()` is idempotent and is the loader's final fallback for any remaining owned worlds/scratch, not a reason to intentionally destroy every world twice.
- `releaseScene` pauses the game, disposes scope and destroys scene objects/deferred objects while retaining the world. `close` awaits that release, then disposes physics. See [app.ts:212–274,277–330](../../../../src/air/app.ts#L212-L330). Never register world destruction in `app.scope`. T12 supplies full scene generations, persistent-object ownership and pending-resource accounting.
- A release receipt with failed/pending components cannot be relabelled clean even if a world subsequently destroys successfully. T12 must finalize handle invalidation and pending-object policy before full lifecycle qualification; T09 initialization-failure fixtures have no unimplemented 3D component teardown dependency.
- ST module disposal drops references after binding destruction; it has no explicit WebAssembly memory destructor. [st-loader.mjs:133–136,167–195](../../../../src/air/physics/box3d/loader/st-loader.mjs#L133-L136). Native live bytes are not `memory.buffer.byteLength`, and neither measures JS GC completion. Bridge-owned debug allocations must have their own accounting if outside the Box3D allocator.
- Loader generations are separate from app preparation generations and future scene/pose epochs. Current same-option prepare shares one Promise/lease, not independent refcounted worlds. Do not add a diagnostic consumer to the app loader and assume disposing it is isolated. Use a separately instantiated ST loader for explicitly isolated diagnostics.

## Real validation plan

Every row below is planned, NOT_RUN for the proposed adapter. Use freshly identified source/WASM/main bundles. Existing lifecycle mocks or historical g results are useful regressions, not substitutions. Preserve failed attempts and raw observations.

### Native and facade prerequisites

1. Live gravity: real sphere/box dynamic body with valid shape and zero damping, separated from contacts; change gravity, read it back and compare the next native velocity with the expected `Δv = g × dt`. Check finite float32 rounding explicitly. NaN, infinities, overflow, malformed vectors and foreign/disposed tokens preserve pose, gravity and counts. Sleeping behavior is tested separately because SetGravity does not wake sleepers.
2. World sleep: let a real supported body settle/sleep under a frozen tick budget, establish native awake count zero, switch sleeping off, establish waking and enabled-state readback, then restore sleep and observe it sleeping again. Test non-boolean rejects without mutation. This is world policy, not B3-C04-SLEEP's later public RigidBody setter coverage.
3. Counts/ownership: assert actual body/shape/contact changes and awake count; destroy/reuse tokens; check module/world/adapter/debug bytes against their own baselines. Preserve ABI-1 count wire rather than changing its stride silently. Verify output buffers and tokens after actual memory growth.
4. Debug: known rotated box and offset sphere, independent expected geometry; actual wire primitives and native fat-AABB enclosure; valid zero flags; invalid bits/size; real constraint fixture and size effect if supported; buffer capacity failure; shape/world destruction cleanup; browser camera submission and screenshot for visible debug claims. None of these require Cocos Collider wrappers.
5. Default material: owned inheriting and explicit-material low-level shapes; verify real native material readback, correct future-shape default, explicit-material preservation, and atomic rejection before changing any shape. Do not pretend the absence of shapes tests propagation.
6. Single-step fault: force a snapshot-copy error after a real native step in an isolated test seam. Retain actual native advancement and fault latch, no replay/second step on the next attempted call, and safe teardown. A separate pre-native validation failure must show zero advancement.

### B3-U01, using the actual PhysicsSystem and real native body

Build an internal fixture that runs the selected real adapter under the actual engine `PhysicsSystem`. Create one facade-owned dynamic body plus box or sphere through a test-only accessor, not a fake `RigidBody` component. Keep T09 assertions on native pose/velocity and callback traces; T10 will separately prove public components.

- At 30/60/120 Hz drive the same 600 fixed ticks with explicitly sufficient `PhysicsSystem.maxSubSteps`. Record each `sync → native step → events → post-sync`, dt and configured solver subdivisions. The body must move according to the real native integrator and finish with equivalent state within frozen tolerance.
- Independently test default `maxSubSteps=1` with a long frame: only one fixed step then retained remainder; subsequent zero-delta postUpdates drain only the permitted amount. Do not expect 30 Hz default pacing to magically match 60 Hz.
- At sub-fixed render deltas observe scene sync without native advancement; at `enable=false` observe sync but no accumulation; at `autoSimulation=false` observe no automatic native step. Reset the existing accumulator through its existing API between controlled cases.
- Prove manual one-dt `PhysicsSystem.step` advances once and does not silently emit events/sync. Extra legacy step arguments reject before advancement under the proposed contract.
- Test `solverSubSteps` 1/2/4/8 as separate configured worlds/pages while total dt per fixed tick stays unchanged. Match dt-driven velocity and trace native call count, not exact substep-dependent positions.
- Collect frame-level Director event counts separately. When 2D is enabled both physics systems emit the same global Director event names; those event totals are not the count of 3D fixed ticks.

Use a transparent recorder around calls to the real binding/adapter for ordering assertions; it must forward to actual WASM and corroborate actual state. A recorder alone is not the physics oracle.
