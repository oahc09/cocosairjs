# Unified motion and force command design

Status: **READ_ONLY_DESIGN_NOT_IMPLEMENTED**, 2026-10-22. This document adds no public API, native export, schema, build input, or qualification result. It does not change the frozen m2 implementation or its 43 inputs. Public decisions below require integrator review before implementation; the original required tests remain required.

## 1. Findings and minimum transaction boundary

The current AIR force/torque/impulse methods write native state immediately. Registering those methods directly as before-step callbacks would allow callback A to modify a body before callback B rejects. The existing motion batch cannot fix that by running before or after a separate loop of force calls.

The minimum safe extension is **one ordered, copied command stream, one pure whole-stream native planner, and one commit phase after all callbacks and all native admission succeed**. Each body needs a shadow origin/rotation/COM/inertia, velocity, force and torque state. Planning must evaluate commands in order, not repeatedly check the unchanged initial state. An explicit reset changes the basis used by subsequent local inputs and offset impulses. It does not retroactively rotate forces already accumulated in world space.

Do not use a single summed impulse: the core clamps linear velocity after each linear impulse, and the existing bridge projects locked velocity components after each impulse. Do not hoist a final teleport ahead of earlier impulses: `impulse A → teleport(preserveVelocity=false) → impulse B` is not equivalent to `teleport → impulse A+B`.

All known refusals must precede the first physics mutation. Unexpected failure after commit begins is not rollback. Native success followed by a failed result copy is committed; an export throw with uncertain completion is unknown and must fault the owner without replay.

### Fixed-core arithmetic and lifetime traps

1. `vendor/box3d/core/src/body.c:1142–1191`: SetTransform updates origin, COM, world inverse inertia and broad-phase bounds; it is a teleport, not continuous motion. Forces/torques are not cleared.
2. `body.c:1309–1351`: SetTargetTransform derives COM velocity and a quaternion-difference angular velocity; an asleep body can otherwise ignore small target motion. Preserve m2's reviewed explicit wake/clear behavior.
3. `body.c:1390–1454`: force/torque operations wake a sleeping body when requested, then accumulate only when awake. The bridge currently accepts only enabled dynamic bodies and requests wake, even for zero force.
4. `body.c:1457–1490`: linear impulse computes `v += invMass*J`, clamps this vector to maxLinearSpeed, then adds `invInertiaWorld * ((point-COM) × J)` to angular velocity.
5. `body.c:1524–1553`: angular impulse computes `q⁻¹*J`, then `invInertiaLocal*localJ`, then rotates the delta back to world before adding. The planner must check this actual operation chain.
6. `body.c:352–358`: waking temporarily takes the core world lock. **Do not hold `world->locked=true` around the new commit loop**. Use the existing synchronous ST/exclusive owner fence, validate unlocked at entry, and reacquire body/sim/state after wakes. Waking an island can move storage for other planned bodies.
7. `solver.c:86–103,109–161,191–218,769–771`: damping/gravity/torque/gyro integration and solver lock/cap processing happen during the single step; accumulated forces/torques reset afterward. Command preflight is not a proof that every possible contact/gyro solver state is finite.
8. `include/box3d/math_functions.h:276–285,331–335`: actual scalar normalization and multiply/add expression order matter. Keep strict float32 operation order/no fast-math; do not silently substitute a double-precision sum or algebraically equivalent inertia expression.

## 5. AIR collection and one-tick execution

The intended sequence is:

1. At the beginning of `world.step`, validate dt/substeps, safe integer counters, app/world/scene ownership, body mass readiness and Node affine/owned-writeback state. Manual step uses this same entry. Scene-only sync cannot drain the queue.
2. Establish a synchronous owner mutation fence and capture the pre-existing accepted queue, body generations and producer roster. Keep separate `tickIndex = nativeStepIndex + 1` and `attemptId`; rejection does not increment completed ticks.
3. Invoke each enabled producer once into a provisional copied command list. Ordinary component force calls route through the same staging path; no binding write occurs. Copy nested arrays/vectors and quaternion inputs immediately. Input aliases cannot alter already queued commands.
4. Reject unsupported mutations and latch candidate errors. On any callback failure, discard all provisional entries, release temporary context/leases, preserve the accepted queue/native state/old snapshot/counters, and surface the failure. Do not claim arbitrary application JS side effects were undone.
5. Merge target intent without reordering physical effects. Add one paired-clear intent for every active target owner with no surviving new target. Validate every participating owner and complete world step readiness again. A hook on body A cannot commit if unrelated enabled dynamic body B is mass-pending.
6. Invoke the unified native apply once; it replans from current native state itself. A separate pure `validateCommandBatch` may provide early feedback but cannot authorize a later stale plan. No callback or configuration write may intervene between final plan/commit and native step.
7. When native status zero establishes commit, mark the entire candidate as consumed before any fallible JS result processing. Mark current observations unavailable, but do not rewrite old copied snapshots or advance step count. On copy/readback failure, report committed, fault and never replay.
8. If result/readiness remain valid, call existing binding step exactly once. Preserve its native-completed/snapshot-failed distinction. Step failure after command commit is not a pre-commit refusal; the world faults and commands are not restored to a retry queue.
9. Only a completed native step advances logical tick state. Copy resulting events/poses, perform existing guarded Node writeback, then leave the execution fence. Event submissions are next-tick inputs. Pending event delivery and app teardown retain their own later milestone qualifications.

This is atomic **admission of commands**, not rollback of an entire solver step. Pre-step readback/output allocations should be reserved before mutation where possible. Allocations inside actual core wake/proxy movement can still fail unexpectedly; those remain unknown/fatal, not hidden as transactional success.

## 6. Native shadow planner and commit

### 6.1 State copied per distinct full body ID

Copy value state only: full ID, type/enabled/sleep state, flags/locks, origin quaternion/position, local/world COM, local/world inverse inertia, inverse mass, current v/w, force/torque, damping, speed caps and fast-rotation flag. Keep the requested managed mass needed to recheck pending geometry. Never cache a `b3BodySim*` or state pointer across commit operations/wakes.

Validate the body table, world generation, full body generations, canonical opcodes/flags, strict booleans, float32 finite inputs, all range/size arithmetic, command sequence, input/output overlap, output capacities and all plan allocations before mutation. Plan all bodies, including later failing members, before any write or wake. The pure pass may allocate/free tracked scratch; it does not promise that allocator capacity or WASM heap size shrinks back.

### 6.2 Ordered transitions

For each command, start from that body's preceding **shadow** state:

- **Reset:** reuse m2 pose/shape safety. `C' = p' + R(q')*localCOM`; `Iworld⁻¹' = R*Ilocal⁻¹*Rᵀ`, matching core expression order. Update basis and optional paired velocity clear/preserve/wake. Retain world force/torque as frozen v1 requires. Disabled reset stores pose without enabling/waking. Static scene reset remains internal-only.
- **Target/target clear:** reuse the unchanged m2 algorithm, admission budgets and one-tick semantics. Only enabled kinematic bodies admit these; dynamic force commands cannot silently coexist on that same body. A target plan is an intent, not an actual reached pose.
- **World/local force or linear impulse:** copy `vector` and `relativePoint`; rotate both for local space using the shadow quaternion. Compute the native absolute point `P = C + offset`, then `r = P - C` with native float32 position arithmetic. Check each intermediate, including derived torque `r × vector`. Record requested offset and rounded actual `r` separately; large positions must not be hidden by a theoretical exact-offset oracle.
- **Force:** shadow `F = F + Fworld`, `T = T + r×Fworld`, checking every intermediate sum in submission order. Multiple individually safe forces can overflow together. A later cancelling force cannot make an already overflowing intermediate acceptable.
- **Torque:** rotate a local torque once, then shadow `T = T + Tworld`. No fictitious offset translation or scale.
- **Linear impulse:** shadow `vRaw = v + invMass*J`; reject unsafe components/length computation; apply the actual core max-linear-speed branch; shadow `w = w + Iworld⁻¹*(r×J)`; check actual intermediates; then apply the existing six immediate velocity masks before the next command. Preserve and report core clamping rather than calling it target admission success.
- **Angular impulse:** use the actual `inverseRotate(q,J) → Ilocal⁻¹*localJ → rotate(q,delta) → w+delta` chain; validate intermediate vectors and then apply the same immediate velocity masks. Do not reuse only a mathematically equivalent `Iworld⁻¹*J` check.
- **Clears, if admitted by the frozen scope:** clear-force zeros only F/T, clear-velocity only v/w, clear-state both. Preserve ordering relative to earlier effects/reset. No guessed/no-op clear.

For all force/impulse variants, retain current enabled-dynamic-only admission and requested wake semantics. Static, kinematic and disabled effects must clearly reject, not return empty success. Zero-force wake behavior should match the existing bridge until a separately reviewed contract changes it.

There is no mass, geometry, type or lock change opcode in the minimum stream. Such writes must finish before collection and be revalidated, or be rejected during collection. Adding them later would require a larger shadow geometry/mass transaction, not a cached old inertia.

### 6.3 Commit strategy

Refactor pure private planner helpers out of motion/body implementation without changing original vendor. Add one new unified native entry that plans the entire copied stream and then replays the validated ordered core operations. Reuse reviewed private clear/mask writes only where the current bridge already implements those semantics. Do not call the existing exported per-command mutators in a loop and propagate their recoverable statuses after earlier writes.

During commit:

- Reacquire full-ID body/sim/state after every operation that can wake/move storage.
- Keep the core unlocked at API entry; no JS callback or asynchronous interleaving is permitted by the outer ST owner fence.
- There is no normal error-status branch after first mutation. An unexpected mismatch/trap must not be returned as `not-mutated`.
- Read final **actual** native pose/COM/body state after all operations. Keep requested commands, shadow expected values and actual readbacks distinct. Qualification may retain per-command observations, but predictions must not be labelled native observations.
- Validate-only performs no output mutation or observation invalidation. Empty apply has no physics mutation and keeps the snapshot current. A nonempty admitted operation may invalidate even when numerically zero because wake/reset semantics can still be real effects.
- Free scratch on all known exits. Unexpected native failure may leave tracked scratch owned by the world for later cleanup; report cleanup failure honestly if the core itself is not safely destructible.

A shadow command planner cannot certify arbitrary future contact/gyroscopic/CCD dynamics. Initial post-step physics oracles must isolate analytically tractable scenes; general solver failures retain their own diagnostic scope.

## 7. Additive wire, facade and failure phases

### Candidate new interface, not yet frozen

Internal facade candidates are `validateCommandBatch(world, commands, dt, substeps): void` and `applyCommandBatch(world, commands, dt, substeps): readonly CommandBodyResult[]`. Public application helpers use RigidBody/owned handle references, never binding tokens or pointers.

Use a new additive stream, not a reinterpretation of m2's 18-word input / 61-float result. A concrete candidate to review before coding is:

- A distinct-body table with full low/high native IDs and managed requested mass. Duplicate body table entries reject; several operations may legitimately refer to one body slot.
- A fixed 16-word operation: body slot, opcode, flags, safe-integer sequence low/high, and 11 payload words. Reset/target uses seven pose words; effect uses vector and offset six words; all unused words are canonical zero. Integer metadata remains uint32, never float32.
- Per-world sequence bounded by `Number.MAX_SAFE_INTEGER`, strict increasing/duplicate rejection, no wrap. The AIR owner owns consumption/de-duplication; the raw binding is not silently an idempotency server for arbitrary repeated calls.
- Candidate limits of 4096 distinct bodies and 16384 operations, admitted before allocation. These are proposed resource bounds, not physical-domain restrictions; confirm exact bounds and error class with the integrator.
- A new explicitly described output with final actual state/pose, planned final values, before-state and copied command identities. Reuse the meanings of existing 49-float state and 10-float pose records, but freeze the new aggregate stride separately. Do not encode sequence/identity through lossy float rows.

The exact aggregate output layout, exports, declarations, input inventory, compile-unit count and evidence inventory must be frozen in a future source checkpoint. They are deliberately **not claimed** by this design. ABI1 can remain additive if every old export/layout retains meaning; schema/build identity must change and stale m2 module/facade mixes must reject. Patch-chain identity remains unchanged unless a separately reviewed actual core patch becomes necessary.

## 8. Required new qualification, with reusable coverage

These are proposed subdivisions of the existing C01/C03/C06/C07/C11/C12/ownership requirements, not passed tests or replacements for full milestones.

1. **Whole-callback refusal:** actual AIR hook A queues force, hook B queues impulse, hook C throws or submits invalid data (including caught invalid submission). Assert no native mutation/wake/step/snapshot change on any body; earlier pre-tick accepted commands retained, provisional operations absent. Explicit subsequent attempt consumes one copy. Include forbidden setter/geometry/Node/reentrant-step entrances and an expired/async context.
2. **Ordered cumulative overflow:** two/three individually finite force or torque additions whose second cumulative float32 intermediate overflows, then a cancelling command; reject the complete batch. Equivalent impulse velocity overflow, local-rotation intermediate overflow, absolute-point subtraction, derived torque and inverse-inertia chain cases. Assert full before/after state, snapshot and ownership unchanged, not just final error code.
3. **Reset order with independent COM/inertia oracle:** translated body `(10,2,3)`, nonzero local COM, rotated anisotropic 2×4×6 box / basic two-sphere compound. Compare force/impulse before versus after rotated teleport, preserve false/true, world/local inputs, and non-diagonal inertia. Assert world F/T retention through teleport, COM-aware offset and no extra Node scale. Retain requested input, pre-command basis, native actual point, all shadow and actual transitions.
4. **Do not sum impulses:** sequential positive/negative impulses crossing the real speed cap, plus offset and pure angular impulses with mixed world locks. Prove exact branch/order differs from aggregate impulse. Immediate locked v/w components ≤1e-6; force/torque accumulators need not be zero on locked axes.
5. **Target coexistence:** mixed dynamic effects and kinematic targets across bodies; reset then target/clear on the same kinematic; target latest-sequence and teleport cancellation; rejected teleport preserves prior target. Preserve m2 damping/cap/lock/sleep tests and all numeric budgets without SetTransform correction.
6. **Tick and frame semantics:** same 600 logical ticks at 30/60/120 Hz, admitted catch-up settings, solver substeps 1/2/4/8, manual step and scene-sync-only. C06 m=2, Fx=4 for 30 ticks gives Δvx≈1; separate Jx=2 once gives Δvx≈1. Continuous contributions occur once per executable tick; ordinary calls once; ConstantForce actual frame calls recorded separately, not falsely equalized.
7. **Lifecycle and identity:** enable/disable/dispose/duplicate-dispose, pause/resume, body disable/type change, full ID reuse and foreign module/world. Clear retains target control; dispose zero cannot erase the next owner's velocity. Pending/continuous counters return to baseline after cleanup. App/event/persist lifecycle remains explicitly scheduled under its original milestone until actually run.
8. **No late known failure:** invalid final member, unrelated pending-invalid body, exhausted step/mutation/sequence counters, bad dt/substeps, invalid quaternion, buffer capacity/alignment/overlap, duplicate table member and malformed unused payload. Native allocation-budget failure before commit leaves states/output canaries unchanged; empty batch leaves snapshot available. Test fixed-core zero-force wake and wake-induced storage moves across bodies.
9. **Failure mechanism versus real physics:** explicit wrappers induce validate-delivery throw, apply-after-real-commit throw, and post-status-zero copy/readback failure. Label these injections, retain actual native before/after state and unchanged step count, and assert no replay. Separate real native computation failures from the injection mechanism.
10. **Memory and retained observations:** force heap growth between calls and after commit before result copy, fresh HEAP views, immutable prior snapshots/results after another step, destroy/reuse/full-generation isolation, tracked plan allocation cleanup. Finite cycles do not prove no ABA forever or whole JS/WASM heap leak freedom.

Run fresh host Debug/Release, fresh ST WASM Debug/Release and separate UBSan-only diagnostics after source freeze. Re-run existing base/ownership/snapshot/geometry/world/body/filter/motion fixtures against the new schema; do not reuse m2 PASS for changed code. Preserve current ASan/LSan and browser infrastructure limits; no browser reroute is proposed.

Use independent parsed arithmetic/geometry oracles, not debug-draw self-validation or planner-returned expected fields. For impulses retain original ≤1e-3 m/s or rad/s budget; exact state/count/order/no-mutation assertions remain exact. Keep the frozen m2 target model ≤1e-4 m/rad and paired velocity budget unchanged. Retain every asserted command/tick sample, original failures, source identity and raw logs, not a truncated best-example list. Float32 planner-versus-native branch agreement is a separate check from physical analytical tolerance.

## 9. Implementation split and preservation

- **Foundation owner:** pure shadow helpers, unified native entry/header, additive facade/types/wire/schema/exports/build source controls and actual C/Node qualifications. No new core patch is currently justified.
- **AIR owner:** producer handles/queue/fence, existing RigidBody paths, world-level consumption and failure state, public export/type-consumer tests, Node/scene lifetime coordination. Do not duplicate the native arithmetic model as a JS simulation.
- **Integrator:** freeze decisions in section 4, public signatures and API-to-test map; review exact future source/evidence inventory and staging consumer gates; preserve source checkpoint before compilation.

This document is the only file written for this task. No m2 input, artifact, old receipt, index or owned inventory is changed. No compiler, runtime fixture, network or deployment action is part of this design pass.
