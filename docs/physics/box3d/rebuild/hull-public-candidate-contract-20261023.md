# Convex MeshCollider source candidate

## Status and lineage

Source candidate only. No engine, native/WASM, or browser build/run was performed by this public-adapter task. The separate actual-source controls use explicit lifecycle, asset and native delegates. They are not C14 physics evidence. All 2,128 formal cells and all nine Gates remain NOT_RUN. The complete C14 denominator remains unchanged, including legal hull, collinear/coplanar/duplicate/nonfinite inputs, output limits, ownership, and failure recovery. The historical recovered patch and initial source input/provenance are unchanged; this is a new implementation against the rebuilt owner, not a claim to restore the old final fixture bytes.

The candidate's base is the exact file inventory in its delivery manifest. Its expected integration dependency is the source67 facade contract: createHull(body, positions, density=1, sensor=false) and validateHull(world, positions). Both copy every float32 input before the native call. Native create success must set immutable committed phase before any ID/readback operation. Missing tokens are not evidence of no mutation. Native validation cooks and frees the same point cloud without shape/body creation. A trap/unknown validation result is a terminal ownership fault, not a clean geometric refusal.

## Public path

1. Existing Cocos MeshCollider setters enter Box3D mutation admission even for same-value assignments. With a live Box3D shape, the proposed value reaches the adapter before the component field changes. Other backends retain the original cache-before-callback and nonnull-only convex dispatch. Optional ITrimeshShape.setConvex does not require legacy backends to implement a new method.
2. Box3DHullShape is the Box3D selector's TrimeshShape. A null mesh remains an initialized, owned pending collider with no native shape. Boolean convex toggles, materials, enabled/disabled state and destruction work while pending. Nonbooleans reject. Null bounds are explicitly unavailable; no fake point/box bounds are published.
3. With a nonnull mesh, convex=false always rejects, including while disabled. Triangle mesh support is not implemented or substituted. All submesh XYZ POSITION streams are copied. Float32, IEEE float16, integer, SNORM and UNORM storage decode to actual finite coordinates. Packed/unreadable formats reject. Hull geometry is the convex point cloud, so indices/winding are not used to truncate or alter the source cloud. No source bounds or primitive box fallback is used.
4. Complete source points are immutable. More than 128 input points are allowed. The native cooker alone determines final volume, retained vertices/faces/full edges and output limits. Duplicate points are retained as input rather than arbitrarily de-duplicated or truncated in JavaScript.
5. Body-local point = (source point + collider center) × world scale. The existing same-Node SharedBody already carries the world origin and rotation; the hull does not apply either twice or substitute the center of mass for body origin. Existing positive-scale, shear, ancestor and runtime-transform restrictions stay in force. This does not close full C11 mirror/scale/hierarchy acceptance.
6. Active replacement uses SharedBody.createHull and the existing events, filters, material roster and native destroy path. Initial/disabled nonnull candidates call native validateHull before publishing adapter caches. No inactive shape is temporarily installed to fake validation. Material owner preparation accepts pending-null geometry and commits the material cache without manufacturing a shape.
7. The facade body handle retains requestedMass. Native create/remove re-normalizes all same-body active geometry, preserving requested total mass and the existing sensor fallback rule. Multiple colliders on one Node share one native body. This does not add child-Node compound ownership.
8. Only a reviewed immutable not-mutated create refusal with no returned token preserves the live world and old caches. A committed/lost-token/unknown create result faults. After a token has returned, later setup or cleanup failure is classified committed even if a later delegated operation itself says not-mutated. The same aggregate rule applies after successful hull destruction followed by owner setup failure. No retry, rollback, contact-history restoration or continuing simulation is claimed.

## Strictly bounded next fixture, not a replacement campaign

Freeze and hash the final facade/schema/native/patch/product/test sources and new Release plus Debug artifacts. Keep current source controls separate. Run the following finite groups once per native variant, retaining every raw result and failed attempt. Fresh source changes require a new attempt identity, never edited fingerprints or reused PASS rows. Native counters/live bytes must return to each run's pre-world baseline after deterministic cleanup; any trap or unresolved cleanup fails the group.

- N1: Unit tetrahedron with sloped-face rays that hit/miss differently from its AABB, copied true hull vertices/planes/edge counts, and positive volume. Include off-origin asymmetric geometry, center, nonuniform positive scale and rotated body origin. Reject any box fallback.
- N2: The same hull plus repeated/interior points with more than 128 source inputs. Require the same real support/ray geometry and bounded output, not refusal based on input count. Reordered input retains valid geometry without a fake same-topology guarantee.
- N3: Collinear, coplanar, coincident, too-few, empty, nonfinite/float32-overflow and genuine over-output-limit inputs. Cover a cloud whose actual hull exceeds each applicable output cap. Validate and create must reject structurally without a leaked hull, shape, body mass change, or old-shape replacement. Include exact cap boundaries only where a real constructed hull achieves them.
- N4: Convex MeshCollider null toggles true/false/true and true/false, while enabled and disabled. No shape creation occurs. Nonboolean edits fail with unchanged exact mesh identity and convex cache. Restore a valid mesh after repeated refusals; disabled invalid cooks reject before caching, then valid onEnable creates real geometry. Keep unsupported nonconvex mesh refusal as a refusal, not a PASS for static mesh support.
- N5: One body with a box plus asymmetric offset hull, add/remove/replace and trigger changes. Check target total mass, local/world COM and the complete COM inertia tensor against independent analytic tetra/box formulas and parallel-axis accumulation. With an effective solid, sensors are excluded. With only valid sensor hull geometry, assert sensorMassFallback. Removing the final effective shape returns massPending; no default-mass simulation is allowed. Restore geometry and verify recovery on the same owned body.
- N6: Initialized real component changes for center, trigger and material, mesh replacement, disable/re-enable, mesh=null, collider destroy and world destroy. Require the real query collider roster to lose retired tokens and resolve the current owned collider only. Preserve body origin, linear/angular velocity and requested mass according to the existing native contract. Check material roster cleanup and pending material updates.
- N7: Native phase fault injection at status0-before-ID-copy, readback after success, trap/unknown, known prewrite geometry refusal, and later setup rejection after a returned token. Assert immutable phase records and owner fault/no-replay behavior separately from clean rejection. No missing-token heuristic may downgrade committed or unknown to not-mutated.

For the independent tetra oracle with positive axis intercepts a,b,c: volume=abc/6, local COM=(a,b,c)/4, diagonal COM inertia is 3m times the sum of the other two squared intercepts /80, and off-diagonal terms are +mab/80, +mac/80, +mbc/80. Apply center/scale, actual rotation and parallel-axis operations explicitly. Compare in scale-aware float32 tolerances; do not use the implementation's own cook or body readback as the expected-value generator.

These are bounded native/source-plus-native groups, not actual Cocos-browser lifecycle acceptance. After they pass on final source, a separate fresh main engine build and real public MeshCollider/EX01 browser run must prove the selector, real Mesh buffers, owner clock, rendering and lifecycle route. Neither stage may silently reduce C14, exclude required negative cases, or promote the full formal matrix/Gates.
