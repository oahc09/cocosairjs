# Application preparation checkpoint

This stage adds the source path for selecting the optional Box3D backend, not an implemented `IPhysicsWorld` or component adapter. No fake world is installed. Missing feature, absent real adapter, and currently unavailable MT/auto modes reject explicitly before native loading; default builtin/Cannon and JavaScript Box2D selection remain unchanged.

The admitted application begins an ownership transaction before either native backend is awaited. Selected 2D preparation completes before selected 3D preparation; final backend registration is synchronous during `PRE_SUBSYSTEM_INIT`. Initialization failures preserve the original error while independently attempting acquired-resource and non-physics cleanup. Normal close releases scene components first, then owned native worlds before modules, then layout/context/diagnostics. Dependencies of a failed native world release remain retained, rather than claiming successful heap teardown.

Existing direct `loadBox2D3` consumers retain a persistent module pin. Application acquisitions share an in-flight load but own distinct leases. A lease cannot destroy a direct consumer's or another lease's world. Dropping JavaScript references only permits later garbage collection; it is not proof of immediate WASM heap reclamation. Backend selection remains prohibited after engine world creation.

Resource keys are unique for the whole attempt, including closing and closed states. A duplicate registration is rejected without invoking a disposer a second time. A genuinely independent late acquisition receives a distinct key and defensively self-releases. This bookkeeping is not a general asynchronous cancellation controller: there is no public app handle during initialization, and a previously returned immutable close receipt cannot certify arbitrary future tasks. T12 scene-generation and component lifetime work is still required.

Review found and first reproduced two defects: repeated same-lease selection incorrectly entered the public ownerless selector, and the closed-attempt branch allowed duplicate keys to schedule repeated disposal. The preserved RED attempt records three failing regression cases. Corrected code is rerun in a distinct GREEN attempt; earlier failures are not rewritten. Earlier development logs without their own source snapshots are diagnostic history, not source-qualified acceptance.

The focused TypeScript lifecycle tests execute real AIR source with mocked engine/native/network dependencies. The additional restored-main Jest tests use actual engine source under HEADLESS/JSDOM. Neither is a real browser, Box3D application physics or 2D/3D coexistence physics result. The separate production-loader tests use real generated WASM but explicit Node filesystem transport.
