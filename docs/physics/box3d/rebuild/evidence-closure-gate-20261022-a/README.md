# Explicit evidence preservation gate

The earlier tracked-file restore checks were accurate for their tracked inventory, but did not prove that ignored stdout/stderr were preserved. The original 316 omitted log files (254,735 bytes) are now retained byte-for-byte; the original receipt scopes are not rewritten. Two additional unique untracked process/source-archive records are also retained rather than silently classified as cache.

For future source checkpoints use `tools/verify/box3d/rebuild-incremental-checkpoint.py` with an explicit delivery manifest and expected HEAD. It refuses absent or uncommitted evidence manifests before producing a bundle. Its required evidence closure is checked separately from every tracked source Git-blob/SHA-256 identity. The legacy generic `rebuild-checkpoint.cjs` restore verifier remains usable, but its tracked-file check is not a complete raw-evidence gate.

The versioned delivery manifest enumerates completed evidence files, exact bytes and modes, declared receipt JSON-pointer references, and exact cache exceptions. Its own bytes are required in the committed tree separately to avoid a self-hash cycle. Unknown ignored or untracked files in the required evidence roots fail. New/changed raw bytes, incorrectly resolved references, raw files disguised as Python cache, changed exceptions, and staged-but-not-committed files fail. An active unfinished file is not a cache; any such exclusion must be explicit and the closure scope remains limited.

This is not a claim that all historical external paths, missing original main paths, toolchain downloads, or archived native outputs are in the source bundle. Their established external artifact identities and restore receipts remain separate. The current declared reference set checks the four material collectors, their frozen input payloads, source freeze, and omitted-log manifest. The root inventory also covers all currently completed Box3D rebuild/verification/native-evidence files.

The local reconstructible Git controls retain original input bytes and mutations in the control script and JSON outputs. Thirteen controls include the original `*.log` omission, exact forced retention, untracked stderr, changed/staged raw, missing or wrong manifest references, cache-boundary checks, and actual committed-tree verification. No physical acceptance status changes.
